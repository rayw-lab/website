# 第一版 MVP 清单与 30 天推进表

> 目标：30 天内上线一个**内容密度高、范围克制**的个人网站第一版。先证明「有人看、有人联系」，再考虑扩展。
> 所有内容素材须先通过 [素材保密分级体系](./material-security-grading.md) 判定后再进入生产。

---

## 1. 第一版数量表（做多少，做完即止）

| 模块 | 数量 | 说明 |
| --- | --- | --- |
| 首页 | 1 | 一句话定位 + 三条核心能力 + 案例/文章入口 |
| 履历页 | 1 | 结构化履历 + PDF 下载入口 |
| 深度案例 | 3 | 每篇均通过案例发布前检查表；宁缺毋滥 |
| 技术文章 | 6 | 优先通用方法论与自主研究；每篇过附录 A 八问题模板 |
| AI 实验 | 2 | 可复现的实验记录，含过程与结论 |
| 可下载 PDF | 1 | 一页纸履历或能力概览；发布前过元数据检查 |
| 联系页 | 1 | 四个交流方向 + 意愿说明模板（见第 5 节） |
| 中英文页面 | 部分页 | 仅首页、履历、联系页做双语；案例与文章第一版只做中文 |

**上限即目标**：第一版不多写一篇案例、不多加一个模块。超出部分记入 backlog，30 天后再评估。

## 2. 不做清单（第一版明确不做）

| 不做 | 原因 |
| --- | --- |
| 会员/登录体系 | 无内容沉淀前毫无价值，徒增开发与安全负担 |
| 评论功能 | 冷启动阶段没有讨论量，还要处理垃圾评论与合规 |
| AI 聊天机器人 | 展示价值低、维护成本高，与「深度内容」定位冲突 |
| 复杂后台/CMS | 静态站 + Markdown 足够；后台是给多人协作准备的 |
| 过多内容分类 | 内容不足 20 篇时分类只会显得空；一层目录即可 |
| 100 篇 AI 生成文章 | 稀释信誉，搜索引擎与读者都能识别；6 篇高质量优于 100 篇灌水 |
| 过度动画/炫技交互 | 拖慢加载、干扰阅读；技术展示靠内容而非特效 |
| 课程/商城/付费墙 | 无受众基础时是空中楼阁 |
| 私密数据/客户素材库 | 违反保密分级体系「敏感内容不上公网」原则（含密码页） |

## 3. 30 天四阶段任务分解

### 阶段一：定位与素材（第 1–3 天）

- [ ] 写出一句话定位与三条核心能力描述（中英双语）
- [ ] 盘点全部候选素材，逐项完成 P0/P1/P2 分级
- [ ] 选定 3 个案例主题、6 个文章主题、2 个 AI 实验主题，确认素材可脱敏或本身为 P2
- [ ] 确定域名、技术栈（静态站生成器 + 托管平台）与仓库结构
- [ ] 建立案例发布前检查表与元数据检查的执行模板

### 阶段二：内容生产（第 4–12 天）

- [ ] 案例 1：初稿 → 脱敏改写 → 通过发布前检查表
- [ ] 案例 2：初稿 → 脱敏改写 → 通过发布前检查表
- [ ] 案例 3：初稿 → 脱敏改写 → 通过发布前检查表
- [ ] 文章 1–3：初稿完成并通过八问题模板自检（附录 A）
- [ ] 文章 4–6：初稿完成并通过八问题模板自检（附录 A）
- [ ] AI 实验 1、2：实验完成，记录整理为可复现文档，标注证据等级（附录 B）
- [ ] 履历页文案 + 一页纸 PDF 制作，PDF 完成元数据清理
- [ ] 首页、联系页文案（含四交流方向与意愿说明）
- [ ] 首页、履历、联系页英文版翻译

### 阶段三：网站开发（第 13–20 天）

- [ ] 搭建站点骨架：路由、布局、导航、中英文切换
- [ ] 实现首页、履历页、联系页
- [ ] 实现案例列表与详情页、文章列表与详情页、AI 实验页
- [ ] PDF 下载功能与下载事件埋点
- [ ] 基础 SEO：语义化标签、sitemap、meta/OG 标签（逐页检查无敏感标识）
- [ ] 访问统计接入（隐私友好型统计即可）
- [ ] 移动端适配与加载性能优化（目标：首屏 < 2s）

### 阶段四：验证与发布（第 21–30 天）

- [ ] 全站内容终审：逐页执行保密分级复核 + 元数据/EXIF/文件名检查
- [ ] 邀请 2–3 位行业内朋友做「组合定位」测试（能否猜出案例客户）与可用性反馈
- [ ] 根据反馈修订内容与交互
- [ ] 域名解析、HTTPS、正式上线
- [ ] 发布后复核：无痕浏览器查源码搜敏感词、下载 PDF 复查元数据
- [ ] 提交搜索引擎收录，配置度量指标基线（见第 4 节）
- [ ] 在 1–2 个合适渠道做一次克制的发布告知
- [ ] 复盘：对照第 4 节指标记录第一周数据，列出第二版 backlog

## 4. 成效度量指标表

| 指标 | 定义 | 第一期观察方式 |
| --- | --- | --- |
| 首页 → 案例点击率 | 首页访客中点击进入任一案例的比例 | 访问统计事件；健康线 ≥ 20% |
| 案例完成度 | 案例页滚动至 80% 以上的访客比例 | 滚动深度事件；反映内容质量 |
| 履历下载数 | PDF 下载次数 | 下载埋点；每周记录 |
| 联系转化 | 通过联系页发起的有效联系次数 | 邮件/表单计数；剔除垃圾信息 |
| 搜索曝光 | 搜索引擎展示次数与点击 | Search Console 类工具；看趋势不看绝对值 |
| 被引用 | 文章被其他网站/社区链接或转载的次数 | 反向链接监测 + 手动搜索 |
| 高质量交流 | 由网站引发的深度技术交流/合作洽谈次数 | 手动记录，逐条备注来源页面 |
| 回访率 | 7 天内重复访问的访客占比 | 访问统计；反映内容黏性 |

**用法**：上线后每周填一次表，只对比自身趋势；30 天复盘时以「联系转化」与「高质量交流」为第一优先指标——它们才是网站存在的目的。

## 5. 联系页：四个交流方向 + 意愿说明模板

### 5.1 四个交流方向

1. **技术交流**：围绕已发布文章/案例主题的深度讨论、勘误与补充。
2. **合作机会**：项目合作、咨询、顾问类邀约（说明领域与大致范围即可）。
3. **演讲与写作**：会议演讲、播客访谈、约稿、联合内容创作。
4. **职业机会**：符合个人方向的全职/兼职机会（可注明当前是否开放）。

### 5.2 明确意愿说明模板（放在联系页顶部）

> 我欢迎以下四类来信：技术交流、合作机会、演讲与写作、职业机会。
> 为了让交流高效，请在来信中说明：**你是谁、来意属于哪一类、具体想讨论什么、期望的下一步**。
> 我会在 X 个工作日内回复上述四类中信息完整的来信；与保密项目相关的细节请勿在初次邮件中发送——涉及敏感内容的深度案例仅通过一对一私密方式沟通，不在公网提供。
> 暂不接受：推销、代发外链、与上述方向无关的群发信息。

## 附录 A：AI 文章八问题模板

每篇技术文章（尤其是涉及 AI 的内容）发布前，逐条回答以下八个问题；答不上来的问题即为文章的薄弱点，须补强或在文中明示局限：

1. **这篇文章解决什么具体问题？** 一句话说清，说不清则选题过散。
2. **读者读完能带走什么？** 可操作的方法、可复用的代码、可验证的结论，至少居其一。
3. **核心论点的证据是什么？** 逐条标注证据等级（见附录 B），不允许无标注的断言。
4. **我自己验证过哪些部分？** 明确区分「我跑过」与「我读到」。
5. **反例和局限在哪里？** 至少写出一个不适用场景或失败案例。
6. **与已有公开内容的差异是什么？** 若与现有文章雷同且无增量，不发布。
7. **是否含任何未脱敏素材？** 对照保密分级体系逐项检查（客户、项目、数据、截图、元数据）。
8. **六个月后这篇文章还成立吗？** 标注时效性强的结论（版本号、模型版本、日期），并注明写作时间。

## 附录 B：证据等级标签表

文章与实验记录中的每个关键结论，须标注以下等级之一（建议在文中以行内标签呈现，如 `[证据: 实际项目验证]`）：

| 标签 | 定义 | 使用要求 |
| --- | --- | --- |
| **实际项目验证** | 在真实项目中应用并取得可观察结果 | 描述须已脱敏；只写模式与量级，不写可定位细节 |
| **Runtime 验证** | 本人在可复现环境中实际运行/测试得出 | 附环境信息与复现要点（版本、配置、步骤） |
| **官方文档** | 来自官方文档/规范/标准 | 附来源链接与版本号；注意文档也可能过时 |
| **多源交叉** | 三个以上独立可信来源一致 | 列出来源；来源互相转载的只算一个 |
| **经验判断** | 基于个人长期经验的判断，未系统验证 | 明示「这是经验判断」，说明经验的适用边界 |
| **推断** | 由已知事实逻辑推导，未经验证 | 明示推理链条与前提；前提变则结论变 |

**规则**：等级只能如实标注，不得拔高；「经验判断」与「推断」不是缺点，隐瞒证据强度才是。读者据此建立的信任，是这个网站最重要的资产。
