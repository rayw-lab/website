# 素材保密分级体系（Material Security Grading）

> 适用范围：个人网站（含中英文页面）、公开演讲/文章、可下载 PDF、案例作品集、社交媒体转发内容。
> 核心原则：**先分级、后创作、再发布**。任何素材在进入内容生产流程之前，必须先完成分级判定；无法判定等级的素材一律按更高保密等级处理。

---

## 1. 分级定义与处理规则

| 等级 | 名称 | 定义 | 处理规则 |
| --- | --- | --- | --- |
| **P0** | 禁止公开（Confidential） | 涉及客户/雇主商业秘密、合同约束、未公开信息，一旦泄露会造成法律或商业损害 | **任何形式均不得出现在公网**：不发布、不暗示、不放入密码页、不放入可下载 PDF；仅可在获得书面授权后降级处理 |
| **P1** | 受控使用（Restricted） | 本身敏感，但经过彻底匿名化/抽象化后可以转化为可公开素材 | 必须走「脱敏改写流程」（见第 5 节）并通过「案例发布前检查表」（见第 5.3 节）后，才能降级为 P2 发布；未通过检查前按 P0 对待 |
| **P2** | 可公开（Public） | 不含任何客户可识别信息、不受保密协议约束、来源为公开事实或自主成果 | 可直接用于网站、文章、PDF、演讲；发布前仍需执行元数据检查（见第 6 节） |

**判定顺序**：先查「禁止公开清单」（命中即 P0）→ 再查「可公开清单」（命中且无附加约束即 P2）→ 其余全部默认为 P1，走脱敏流程。

**灰区规则**：拿不准的素材一律升一级处理（P2 存疑按 P1，P1 存疑按 P0）。分级的成本远低于泄密的代价。

---

## 2. 禁止公开清单（P0，命中任意一条即禁止）

以下信息**在任何页面、任何文件、任何图片中都不得出现**，包括正文、图表、截图角落、文件名、URL、元数据：

1. **未公开的客户车型**：车型代号、开发中项目名称、上市前的产品信息、可反推车型的配置组合。
2. **项目编号**：客户内部项目号、平台代号、工单/需求编号、内部系统 ID。
3. **合同金额**：报价、合同额、预算、人天单价、商务条款、付款节点。
4. **量产节点**：SOP 时间、里程碑计划（A/B/C 样、PT、PPAP 等）、延期信息、排产计划。
5. **内部能力差距**：客户或雇主未公开的技术短板、缺陷统计、失败项目细节、审计结论。
6. **未公开架构**：客户尚未对外发布的系统架构、网络拓扑、软件平台设计、接口定义、技术选型决策记录。
7. **供应商分工**：供应链关系、各供应商承担的具体范围、定点结果、竞争对手信息。
8. **人员与组织**：客户/雇主的组织架构、具体人名、职位、汇报关系、团队规模、联系方式。
9. **内部载体**：内部截图、PPT、邮件、会议纪要、聊天记录、评审记录——**无论内容本身是否敏感，载体本身即 P0**（内部模板、水印、页眉页脚都会暴露来源）。
10. **元数据与标识**：PDF 属性中的作者/公司字段、图片 EXIF、文档修订历史、批注、隐藏图层、以及**文件名/路径中含客户名、项目号、内部代号**的情况（详见第 6 节）。

> 注意：以上信息「换个说法暗示出来」同样属于泄露。例如「某德系豪华品牌 2027 年将量产的旗舰车型」——组合起来可唯一定位客户与项目的描述，等同于直接点名。

---

## 3. 可公开清单（P2）

以下素材可以公开使用，但发布前仍需过一遍元数据检查：

1. **已公开事实**：客户官方新闻稿、公开财报、发布会内容、已上市产品的公开参数、公开招聘信息中已披露的技术栈。引用时注明公开来源。
2. **通用方法论**：不绑定任何具体客户的工程方法、流程框架、工具链使用经验、行业标准（如 AUTOSAR、ISO 26262）的通用解读。
3. **授权案例**：已获得客户**书面授权**（邮件确认亦可，需存档）的案例，且严格按授权范围披露，不得超出授权内容一个字。
4. **匿名抽象案例**：P1 素材经过完整脱敏流程并通过发布前检查表的产出（见第 5 节）。
5. **自主研究**：业余时间、用自有设备与公开资料完成的研究、开源项目、个人实验、AI 实验记录——前提是未使用客户数据、客户环境或受保密约束的知识。

## 4. 密码页 ≠ 授权：敏感内容的正确处理方式

**核心规则：给页面加密码不等于获得了披露授权。** 加密页面在法律上仍然是「向第三方披露」，且技术上存在被爬取、被分享、被搜索引擎缓存的风险。

- **禁止**：把 P0/未脱敏的 P1 内容放在「密码保护页」「隐藏链接」「robots.txt 屏蔽页」上——这些手段只是访问控制，不改变披露性质。
- **正确做法**：确有必要向特定对象（如面试官、潜在合作方）展示敏感度较高的深度案例时，采用**一对一私密作品集**：
  - 内容单独成册（PDF 或线下演示），**不托管在公网**，不上传到网站服务器、不放网盘公开链接；
  - 通过点对点方式（当面演示、一次性加密传输）提供，并明确告知对方保密预期；
  - 私密作品集内容同样必须完成脱敏，只是脱敏后保留的技术深度可以比公开版更高；
  - 每次分享记录对象与日期，便于追溯。
- 网站上可放的最深内容 = 通过发布前检查表的 P2 版本。私密作品集是「深度补充」，不是「绕过分级的后门」。

## 5. 脱敏 ≠ 删客户名：匿名化/抽象化操作指南

只把客户名替换成「某客户」是**不合格的脱敏**。读者（尤其是同行业读者）可以通过项目细节、时间线、技术栈组合、图表样式反推出客户身份。合格的脱敏是让案例**无法被唯一定位**。

### 5.1 匿名化操作（针对可识别信息）

| 操作 | 做法 | 示例 |
| --- | --- | --- |
| 泛化行业角色 | 客户名 → 行业类别 + 模糊规模 | 「X 公司」→「一家头部主机厂」（若头部只有两三家，进一步模糊为「一家主机厂」） |
| 模糊时间线 | 具体年月 → 相对时长 | 「2025 年 3 月至 9 月」→「约半年的迭代周期」 |
| 重绘图表 | 内部截图/图纸一律不用，用自己的工具重画抽象示意图 | 内部架构图 → 手绘风格的通用分层示意 |
| 改写数据 | 精确数值 → 数量级或比例 | 「缺陷率从 3.7% 降到 0.9%」→「缺陷率下降约 75%」 |
| 剥离组合特征 | 检查多个非敏感细节组合起来是否可定位客户 | 「德系 + 电子电气架构 + 某总线技术」若组合唯一，则删除其中一项 |

### 5.2 抽象化操作（针对技术内容）

1. **提炼问题模式**而非复述项目经过：把「我在 X 项目中做了什么」改写为「这一类问题的一般形态是什么、我的解法框架是什么」。
2. **用公开等价物替换内部实现**：内部工具/平台 → 同类开源或商用工具的通用概念。
3. **重新构造示例**：代码、配置、报文示例全部重写，不复制任何来自客户环境的片段。
4. **验证可迁移性**：脱敏后的方法论应当对第三方读者依然成立——如果删掉客户背景后文章不成立，说明卖点是保密信息本身，该案例不适合公开。

### 5.3 案例发布前检查表（每篇案例必过，全部勾选后方可发布）

- [ ] 全文无客户名、车型名、项目编号、内部代号（含拼音缩写、首字母暗示）
- [ ] 无合同金额、报价、预算、商务条款
- [ ] 无量产节点、里程碑日期等可对应到具体项目的时间信息
- [ ] 无客户内部能力评价、缺陷统计、未公开架构细节
- [ ] 无供应商分工、定点、竞争关系信息
- [ ] 无具体人名、职位、组织架构信息
- [ ] 所有图表均为自绘，无内部截图/PPT/邮件/纪要素材（含裁剪后的局部）
- [ ] 数据已改写为数量级/比例，无法回推原始数值
- [ ] 「组合定位」检查：让一位熟悉该行业的第三方读一遍，确认无法猜出客户
- [ ] 若为授权案例：披露内容逐条对照授权范围，未超出
- [ ] 文件元数据与文件名检查已完成（见第 6 节）

## 6. 文件元数据 / EXIF / 文件名检查项

发布任何文件（图片、PDF、Office 文档、代码包）之前，逐项执行：

### 6.1 图片

- [ ] 清除 EXIF（拍摄设备、GPS 坐标、拍摄时间、软件信息）：`exiftool -all= 文件名` 或导出时选择「不含元数据」
- [ ] 截图检查四角与背景：任务栏、浏览器标签页、书签栏、通知弹窗、窗口标题中是否带出客户名/项目名/内部系统
- [ ] 图片内无水印、页眉页脚、内部模板样式

### 6.2 PDF / Office 文档

- [ ] 文档属性清空：作者、公司、经理、主题、关键词字段（PDF 用 `exiftool` 或导出前在源文档中清除）
- [ ] 删除修订历史、批注、隐藏文字、隐藏图层、嵌入对象
- [ ] 从干净的源文件重新导出，而不是在旧文件上修改（旧文件可能残留增量更新历史）
- [ ] PDF 内嵌图片同样执行 6.1 检查

### 6.3 文件名与路径

- [ ] 文件名不含客户名、项目号、内部代号、版本暗示（如 `XX项目_终版_v3` 一律重命名为语义中性的名称，如 `case-ee-architecture.pdf`）
- [ ] 压缩包内部的目录名、子文件名同样检查
- [ ] 网站 URL、图片 alt 文本、`<title>`、OG 标签中无敏感标识

### 6.4 发布后复核

- [ ] 用无痕浏览器访问已发布页面，右键查看源码，搜索客户名关键词
- [ ] 下载已发布的 PDF/图片，用 `exiftool` 复核一遍元数据确实为空

## 7. 与 MVP 内容生产的衔接

- 所有进入 [MVP 清单](./mvp-checklist.md) 内容生产阶段的素材，必须先在本体系下完成分级。
- 案例（3 篇)：默认按 P1 处理，逐篇走第 5 节流程。
- 文章（6 篇）与 AI 实验（2 篇）：优先取材于 P2（通用方法论、自主研究），避免触碰脱敏成本高的素材。
- 可下载 PDF（1 份）：发布前执行第 6.2 节全部检查项。
