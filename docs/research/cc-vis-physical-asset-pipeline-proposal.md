# 实模资产管线专项立项书（视觉 81→85 显式承接路径）

## 1. 问题定义

程序化打磨（Tier A/B/C 全清单已施工）后视觉 81；剩余 4 分缺口的扣分点全部为**实模密度/工艺**类：
- V4 76：远景楼体重复窗格、缺实模立面细节（Orion 锚 = 每视角近/中/远三层实模可读）
- V7 85：城市面仍通用霓虹语汇（招牌/道具为程序化原语 + 贴图）
- V2 83：材质缺手工精修/IBL（程序化材质的上限段）

## 2. 方案（Blender 实模产线）

### 2.1 范围（首批 5 栋 hero 楼 + 街道段）
- 3-5 栋 hero 楼 **实模立面**（Blender 建模：窗框几何、檐口、墙面分割、空调外机/管线细节），导出 glTF+KTX2（FacadeKit.glb 同管线，加载分档复用）
- 2-3 组 **实模街道道具**（路灯杆、报刊亭、护栏、垃圾桶实模化，替换程序化原语）
- **1 组实模标牌**（立体字 + 灯箱框，替换 TextCanvas 平面贴标）

### 2.2 管线
```
Blender 4.x 建模 → glTF 导出（Draco 压缩）→ KTX2 纹理转码
→ FacadeKit.glb 增量打包（既有管线，零新代码路径）
→ 加载分档：Q0 全量 / Q1 降采样 / Q2 不加载（既有纪律零改动）
```

### 2.3 预算影响（G-A′ 红线）
- world JS：**零增量**（资产走 glb 不走代码）
- glb 增量：首批估算 3-8MB（Draco+KTX2 后）——**需指挥官裁定是否破当前资产配额**（现 FacadeKit.glb 80KB → 增至 MB 级是数量级变化，可能需拆包/流式）
- 加载分档：Q2 不加载、Q1 延迟加载策略沿用

### 2.4 预估收益（对标 rubric 锚点）
| 维 | 现 | 专项后预估 | 依据 |
|---|---|---|---|
| V4 | 76 | **85±3** | 实模三层密度成体系（Orion 锚 90-100 的主扣分项消除） |
| V7 | 85 | **88±2** | 实模招牌/道具叙事一体感 |
| V2 | 83 | **85±2** | 实模材质 + 环境反射贴图（IBL） |
| V1 | 82 | **84±2** | 首幕背景实模楼群提升定帧质感 |
| **总分** | **81** | **85±3** | 双评 |Δ|≤5 确认后登记 |

## 3. 周期与成本

| 阶段 | 内容 | 墙钟 |
|---|---|---|
| P1 建模 | 3-5 栋 hero 楼实模（Blender） | 3-5 天（人工） |
| P2 材质/纹理 | KTX2 转码 + 灯光适配 | 1-2 天 |
| P3 打包/接线 | FacadeKit 管线增量 + 加载分档验证 | 1 天（自动化） |
| P4 双评登记 | AL-VIS 三族重评 + score-loop + 看板 | 0.5 天（自动化） |

总计 **5-8 天**（含人工建模，指挥官或外包排期）。

## 4. 风险

| 风险 | 缓解 |
|---|---|
| glb 增量破资产配额 | 拆包/流式加载（FacadeKit streaming 预案已有——budget.streaming 声明字段） |
| Blender 建模质量不达 Orion 锚 | 首批只做 1 栋打样 → 双评确认方向 → 再批量 |
| Q2 档止损纪律破坏 | 既有 Q2 不加载纪律零改动 |
| 加载时间感知 | Q0 首屏不阻塞（异步流式），进度指示沿用 Reveal 光柱 |

## 5. 指挥官决策页

| 决策 | 选项 |
|---|---|
| D-6 实模专项是否立项 | ①立项（排 P1 人工建模排期）②不立项（视觉 81 收口，85 留作长期） |
| D-6a glb 配额 | 允许 3-8MB 增量 / 需拆包方案 / 维持 80KB 上限（= 不立项等效） |

> 立项 ≠ 立即施工：排期与建模资源归指挥官。本立项书 = 决策输入。
