## 1. Executive Summary

bruno-simon.com 把作品集做成一辆能开的车：物理引擎负责「好玩」，空间分区负责「导航」，成就与排行榜负责「留下来」。2019 版用 3 个月业余时间证明「游戏化作品集」能一夜爆红（首周 16 万访问）；2025 版用 14 个月把它升级成真正的游戏级产品，拿下 FWA 年度大奖双料。它最值得借鉴的不是 3D 本身，而是三件事：**开场 10 秒内用「玩」教会操作**、**一切 UI 尽量长在世界里（diegetic）**、**为每条失败路径（卡住、低配、服务器宕机）预留出口**。对磊哥的站点而言，可以照抄它的引导手法与空间语法，但必须改造它的「信息效率」短板——解决方案经理的访客没有义务开车找简历。

## 2. 体验时间线：从首屏到离开的逐帧拆解

以 folio-2025 为主线（2019 版差异随注），按真实访客旅程逐步拆解。情感曲线采用五档标记：😐 平静 / 🙂 好奇 / 😲 惊讶 / 😄 愉悦·心流 / 🤩 峰值·想分享，⚠️ 表示该步骤存在流失风险。

### Step 0：点击链接之前（分享语境）

| 维度 | 内容 |
|------|------|
| 用户看到 | 社交场景中的推荐语自带钩子：「你可以在他的网站里**开车**」「别在 deadline 前打开」；2019 版连浏览器标签页标题都有随车前进/倒退移动的 emoji 小车 |
| 用户做什么 | 带着「网站怎么可能是游戏？」的预期落差点开链接 |
| 系统反馈 | OG 分享图（`static/social/share-image.png`）直接展示玩具车 + 低多边形世界，预告体验类型 |
| 情感 | 🙂 好奇。**关键洞察：viral 站点的第一屏其实在别人的转发语里**，预期管理从站外就开始了 |

### Step 1：首屏加载

| 维度 | 内容 |
|------|------|
| 用户看到 | 不是 HTML 进度条，而是**画在 3D 地面上的一个发光圆环**，沿圆周按加载进度逐渐补全（源码 `Intro.js`：`RingGeometry` + 按角度 discard 的 TSL shader，圆环中心就是出生点） |
| 用户做什么 | 等待。桌面端良好网络约数秒；低端设备或首次 shader 编译可达 30–60 秒（HN 多人报告） |
| 系统反馈 | 圆环补全后以 `power4.in` 缓动收缩消失——加载结束本身就是一段动画，无缝衔接世界显现（`Reveal` 模块渐显） |
| 情感 | 😐→🙂，但 ⚠️ **本步是最大流失点**：HN 原话 "it takes so long to load that I've closed the tab before seeing anything because it looks broken"。diegetic loader 美则美矣，部分用户不认识它是进度条 |

> 2019 版差异：有一个显式的 **Start 按钮**。Bruno 在 Medium 案例中坦白：这个按钮存在的真实原因是浏览器音频策略——声音必须在用户点击/触摸后才能播放，键盘输入不算。「Start 按钮的故事就是这么来的。但最终它成了放置加载器的完美时机。」——**Start 按钮是技术约束倒逼出来的设计，却顺手完成了期望设定与仪式感**。这正是磊哥设想中 "Start here" 的原型。

### Step 2：入世（出生瞬间）

| 维度 | 内容 |
|------|------|
| 用户看到 | 2019：宇宙从地面「弹出」、小红车从天而降落地弹跳两下；2025：世界渐显，车出现在出生点，旁边浮着一块操作提示牌和一个音量按钮（均为 3D 物件，非 HTML） |
| 用户做什么 | 还没做什么——正在被「教」 |
| 系统反馈 | 车落地的弹跳是刻意设计：「让用户第一眼就注意到这个世界有物理」（Medium 原文）。2025 版提示牌会**根据输入设备自动换贴图**：键鼠 / Xbox 手柄 / PS 手柄 / 触屏各一套（源码 `Intro.js` 的 `updateTexture()` 按 `Inputs.MODE_*` 切换） |
| 情感 | 😲 惊讶。「这居然是个游戏」的认知在 3 秒内完成 |

### Step 3：首次输入（第一次踩油门）

| 维度 | 内容 |
|------|------|
| 用户看到 | 地面/提示牌上的方向键图示（2019 版说明直接写在地上，全站没有别的文字 UI） |
| 用户做什么 | 按下方向键或 WASD；移动端单指拖动 |
| 系统反馈 | 车立刻响应：引擎声随油门变调、轮胎在草地留下压痕（`Tracks` 模块）、倒车/刹车时**尾灯真的会亮**（2019 就有的细节） |
| 情感 | 😄 掌控感建立。输入→反馈延迟低于 100ms，这是「网站」变「游戏」的换血瞬间 |

### Step 4：第一次破坏（撞倒名字）

| 维度 | 内容 |
|------|------|
| 用户看到 | 出生点正前方立着 3D 立体字 "BRUNO SIMON" |
| 用户做什么 | 几乎必然一头撞上去 |
| 系统反馈 | 字母块被撞飞、翻滚、发出随机化的碰撞声。Medium 原文：「车的初始摆位不是随机的：我要确保用户在开场就撞上我的名字，从而最大化『万物可撞』的可理解性」 |
| 情感 | 🤩 第一个峰值。**用世界上最贵的东西（自己的名字）当教学道具**，一次交互同时完成：物理教学 + 品牌记忆 + 「这里允许破坏」的许可颁发。首页欢迎语的反心理暗示「And don't break anything!」在此刻兑现成幽默 |

### Step 5：漫游（自由探索期）

| 维度 | 内容 |
|------|------|
| 用户看到 | 道路铺装（tiles）向远处延伸、路牌、发光的白色菱形交互点、远处地标（拱门、赛道看台、保龄球道）；风吹草动、天气与昼夜实时变化（全球玩家同步同一套天气） |
| 用户做什么 | 沿路开、抄近道压草地、按 M 开地图、按空格跳、按数字键玩液压弹跳（低趴车绝活）、按 H 鸣笛 |
| 系统反馈 | 树叶在车前自动缩小防止挡视线（SDF 树叶技术）；驶入交互区域时区域展开/高亮；接近可交互物时出现 "Interact" 上下文按钮；卡住时有 "Unstuck" 一键脱困 |
| 情感 | 😄 心流。探索由「信息气味」驱动（详见第 4 章），不是被菜单驱动 |

### Step 6：进入作品区（回归「作品集」本职）

| 维度 | 内容 |
|------|------|
| 用户看到 | Projects（客户项目）与 Lab（实验）两个展区，展板、屏幕、操作台全部是 3D 模型 |
| 用户做什么 | 开到展位前按 Enter/A 键交互，翻页浏览项目，点击跳转外链 |
| 系统反馈 | 相机接管运镜对准展板（2019 版进入项目区时相机自动拉高俯视以保证可读性——测试者反馈「读不清」后加的补救）；**click、scroll、键盘、触摸手势全部在 3D 里重建**（Awwwards 案例原文），翻页有专门用 GarageBand 合成的音效 |
| 情感 | 🙂→😄。信息获取效率低于传统网页，但「在游戏里翻别人简历」的新奇感形成补偿 |

### Step 7：元游戏（把访客变玩家）

| 维度 | 内容 |
|------|------|
| 用户看到 | 成就系统（含解锁计时）、赛道 Circuit（起点旁立着当日 Top 10 排行榜，每日重置）、Whispers 留言火苗（全球玩家留言，上限 30 条、每人 1 条、30 字符、带国旗、OpenAI moderation 审核）、cookie 摊位的全球计数器、掉进深渊会累加的祭坛计数 |
| 用户做什么 | 刷圈速、集成就换车漆皮肤（red/orange/white/black/flames/abyssal 六款）、留 whisper、故意跳崖 |
| 系统反馈 | 成就解锁通知（`Notifications` 模块）、皮肤即时换装、排行榜实时写入；服务器宕机时显式降级：「Server currently offline. Scores can't be saved.」但**整个作品集离线照常可玩**（官方声明：the portfolio works without it） |
| 情感 | 🤩 第二峰值 + 复访钩子。HN 用户实录：「和儿子玩赛道想不通别人怎么跑进 20 秒的」 |

### Step 8：离开与分享

| 维度 | 内容 |
|------|------|
| 用户看到 | Behind the scene 面板（完整技术栈自白 + 开源仓库 + devlog + CC0 音乐下载）、Discord 社区入口、社交图腾（可以撞倒但链接仍可点） |
| 用户做什么 | 转发（自带「你能开车」的转述钩子）、去 GitHub 看源码、订阅 devlog、录速通视频 |
| 系统反馈 | 开源 + devlog 把「访客→玩家→传播者→学员（Three.js Journey 课程）」的漏斗闭环 |
| 情感 | 🤩→🙂 余韵。注意冷数据：2019 版**平均停留只有 54 秒**——viral 不等于人人深玩，多数人「哇一下就走」，但那一下足够触发转发 |

### 情感曲线总览

```
情绪
🤩                    ▲撞名字            ▲成就/圈速/彩蛋
😄               ▲首次开动         ▲▲▲ 漫游心流
😲          ▲世界显现+车落地
🙂     ▲点开链接                                    ▲离开·转发
😐  ▲加载(风险谷)
    └────┴──────┴─────┴──────┴────────┴──────┴──────→ 时间
    加载   入世    首输入  破坏教学   漫游/作品   元游戏   离开
```

设计要点：**峰值前移**（撞名字发生在前 30 秒内）+ **双峰结构**（教学峰 + 元游戏峰）+ **谷底止损**（加载谷有 diegetic 动画兜着，但仍是最大流失点）。

## 3. Onboarding 设计解剖

### 3.1 两代引导策略对照

| 环节 | folio-2019 | folio-2025 |
|------|-----------|-----------|
| 入场门 | **显式 Start 按钮**（本质：音频解锁 + 加载器 + 仪式感三合一） | 无门，加载环走完直接入世（音频改为世界内 3D 音量按钮 + 首次交互解锁） |
| 操作教学 | 说明**直接写在地面上**，全站无 HTML 教学层 | 出生点浮空 3D 提示牌，**按输入设备热切换**键鼠/Xbox/PS/触屏四套图示 |
| 物理教学 | 世界弹出 + 车从天而降弹跳 → 「注意，有物理」 | 同思路，配合 Reveal 渐显 |
| 可撞性教学 | 车的初始朝向正对 "BRUNO SIMON" 立体字 | 保留同款手法 |
| 进阶操作 | SHIFT 跳跃**不教**——上线后发现非玩家用户根本不知道，补加了提示但刻意不放在开场（防信息洪水） | 控制面板全量收录 + 成就系统反向教学（想拿成就就得学会液压/漂移） |
| 迷路救济 | 无系统化方案 | "I'm stuck!" 一键传送最近重生点、R 键 respawn、Reset 重置所有物体、M 键地图 |

### 3.2 设计语言：为什么这套引导有效

1. **教学即玩耍（learning by crashing）**。没有 tutorial overlay、没有「下一步」浮窗。第一课（会动）靠落地弹跳，第二课（会撞）靠撞名字，第三课（有路）靠地砖。每一课的「教材」都是玩具本身。
2. **说明文字是世界的一部分**。指令写在地上/牌子上，镜头转开它就自然退场，不存在「关闭教程弹窗」这个反沉浸动作。Bruno 的原则：「Everything had to be part of the 3D world…I chose to have no interface so that the experience could be as immersive as possible.」
3. **输入设备自适应是尊重感的来源**。检测到手柄立即换成对应厂牌的键位图（Xbox 与 PS 分开做），触屏用户看到的是手势图。这个细节告诉玩家：「我知道你怎么来的。」
4. **渐进披露有明确的失败教训**。2019 版 SHIFT 跳跃的不可发现性是 Bruno 自己复盘的第一大 UX 事故：对开发者显然的事对非玩家完全不显然。修复方式不是在开场堆说明，而是把进阶操作挪到「玩家已经上手之后」才出现。

### 3.3 失败模式清单（引导层）

| 失败模式 | 证据 | 教训 |
|---------|------|------|
| diegetic loader 不被识别为加载器 | HN：「circle loaded and then nothing」「It has no load progress indicator」 | 世界内加载动画需要冗余的文字/百分比锚点 |
| 加载完成后假死 | HN：iOS「loading bar completes and the app freezes for 30 sec」（shader 编译/纹理上传） | 在 loader 阶段预热 shader，或明示「正在初始化」 |
| 非玩家不识 WASD | 2019 SHIFT 事故；HN 有用户拿到世界后不知所措 | 键位图示 + 前 5 秒无输入时的脉冲提示是必要的 |
| 无 2D 逃生门 | HN：「if you google searched for some info and stumbled on this, I'm not sure you'd even know what's on offer」 | Bruno 可以不做（他的受众就是来看技术的），**磊哥必须做** |

### 3.4 多输入适配的完整答卷

folio-2025 对四类输入端做了完整而非敷衍的适配（详表见第 5 章）：

- **键鼠**：WASD/方向键驱动 + 左键拖拽自由视角 + 滚轮缩放，快捷键覆盖全部元操作（地图/静音/留言/重生）；
- **触屏**：单指=开车、双指=视角/缩放、点车=跳——把三类操作压进两根手指，且完全无虚拟摇杆（2019 版用过虚拟摇杆+按钮，2025 改为更激进的直接操纵）；
- **手柄**：LT/RT 油门刹车、左摇杆转向按压鸣笛、右摇杆视角按压缩放、肩键液压——完全按主机赛车游戏惯例映射，Start=暂停、Select=重置；
- **降级路径**：手柄图示区分 Xbox/PS 图标体系；触屏端自动切低画质预设（关水面模糊、景深，降阴影分辨率）。

## 4. 空间叙事架构

### 4.1 世界分区（源码实证）

folio-2025 源码 `sources/Game/World/Areas/` 共 14 个区，可归纳为四个功能层：

| 层 | 区域（源码文件名） | 承担的叙事职能 |
|----|-------------------|---------------|
| **信息层**（作品集本职） | Landing（出生点）、Career（履历）、Projects（客户项目）、Lab（实验作品）、Social（社交图腾）、BehindTheScene（技术自白） | 传统网站的 Home/About/Work/Contact 全部空间化 |
| **游戏层**（留存钩子） | Circuit（赛道+每日排行榜）、Bowling（保龄球）、Achievements（成就墙） | 给「玩家型访客」提供目标与挑战 |
| **社交仪式层**（轻多人） | Cookie（接受饼干的全球计数器玩笑）、Altar（跳崖祭坛计数）、Whispers（30 条全球留言火苗） | 让单机世界有「别人来过」的体温 |
| **彩蛋层**（人格注入） | TimeMachine（时光机——通往 2019 旧版！）、Toilet（厕所）、Easter（复活节彩蛋） | 拒绝完美主义人设，制造转发谈资 |

2019 版结构简单得多，共 5 段：intro（教学）→ **crossroads（十字路口 hub）** → playground（物理游乐场）→ projects → 联系信息。典型 hub-and-spoke：十字路口是导航中枢，所有区域从这里辐射。2025 改为开放式岛屿，靠道路网与地标导航。

### 4.2 用 3D 空间替代传统导航的五个机制

1. **道路即导航栏**。2019 版地砖 tiles「像一条路径，让用户轻松理解那个方向有更多东西」（Medium 原文）；且 5 种地砖随机旋转、相邻不重样——功能性铺装同时是美术资产。
2. **墙体即边界**（防止用户开出信息架构之外），**路牌即面包屑**。
3. **地标即一级菜单**。赛道看台、保龄球道、拱门在远景可见，「看见即知道那里有内容」——视线可达性代替了 sitemap。
4. **交互区即 hover 态**。驶入可交互区域时区域会展开/抬升，鼠标悬停同样触发——把 hover 反馈做进了地形。
5. **地图即 sitemap 兜底**。M 键呼出全局地图，承认空间导航必有迷路率，给出上帝视角救济。

### 4.3 信息气味（information scent）如何铺设

- **视觉气味**：白色菱形交互点（HN 用户第一反应就是「click the white diamonds」）、发光物件、道路铺装密度递增暗示「快到了」；
- **听觉气味**：全部物件音效空间化——左声道传来篝火声=左边有东西可看（Awwwards 案例明确把声音列为 UX cue）；
- **动线气味**：出生点→名字→第一段路的黄金 30 秒动线经过刻意排布，教学区出口直通 hub；
- **好奇心气味**：达不到的高台、可疑的深渊、上锁的成就（「Unlock at ****」连解锁条件都打码）制造「这里还藏着东西」的持续张力；
- **自我引用气味**：TimeMachine 区把 2019 旧版做成世界内的「历史遗迹」——版本迭代本身成了叙事素材。

### 4.4 一个值得偷的观点

Bruno 没有「用 3D 装饰网页」，而是**把网页的每个原语翻译成空间原语**：导航栏→道路，hover→地形展开，点击→车头撞/Enter 键，滚动→3D 内重建的滚轴，footer→世界边缘的社交图腾。翻译是系统性的，所以体验是自洽的。模仿者最常见的失败是只翻译了 50%——半游戏半网页，两头不靠。

### 5.4 语法设计观察

- **「确认」有两套并存**：物理确认（把车开进区域/撞上去）与按键确认（ENTER/A）。前者管发现，后者管深入——避免了「开车误触进入项目详情」的误报。
- **「返回」被拆成四档**：退出面板（A/关闭）→ 脱困（Unstuck）→ 重生（R）→ 全局重置（Reset）。破坏系玩法必须配等级化的撤销。

## 6. 视觉与美术方向

### 6.1 低多边形 + 「假光照」美学（2019 奠基）

- **风格源头**：巴西艺术家 Gustavo Henrique 的「微缩彩色建筑、大平面、微圆角」风格（Bruno 在 Medium 亲自点名）；
- **场景里没有一盏真灯、没有一片实时阴影**：物体着色全靠 **matcap** 贴图（按相机空间法线采样的预烘焙光照球）；静态阴影 Blender 烘焙成 PNG-8，动态物体脚下垫一张随位置/旋转/离地高度实时变换的阴影贴片；
- **地板是一张 JS 生成的 2×2 像素渐变纹理**拉满全屏，四角颜色由 GPU 自然插值；
- **假光反弹**：面越朝下、离地越近就越染上地面的橙色——一行点积运算模拟 GI；
- **后期**：屏幕上下两条廉价模糊 + 左侧一大团镜头光斑「假装」有一颗暖阳。

结论：2019 版的高级感是**用美术直觉抵消渲染预算**的教科书——先定调色板和光的方向感，再倒推最便宜的实现。

### 6.2 程式化自然 + 实时天气（2025 跃迁）

- 全世界在 Blender 建模，靠命名约定驱动行为（如 `refLandingPhysicalFixed` 自动生成固定物理体）；
- **草地 78,400 根草，每根 1 个三角形**，只铺相机视野并无缝循环，看起来铺满全岛；水面、地形、雨同用循环技巧；
- 三种树（桦/橡/樱），树干实体、树叶为面向相机的 SDF 面片——**车前树叶动态缩小**保证驾驶视线，美术为可用性让路的典型案例；
- 全球同步的昼夜、四季、风雨雪电、龙卷风系统——世界「活着」且所有访客共享同一时刻；
- 配色统一进一张 **palette 纹理**，所有合并模型靠 UV 采色，保证全岛色彩系统性；
- 压缩管线：纹理 ETC1S/UASTC（GPU 友好格式）、模型 DRACO 量化、UI 图 WebP。

### 6.3 UI 在 3D 世界中的呈现：为何尽量不用 HTML

Awwwards 案例原文：「为了保住沉浸感，我尽量避免传统 HTML UI。这意味着**为界面制作真正的 3D 模型，并在 3D 里重建全部标准交互**：点击、滚动、键盘输入、触摸手势，甚至手柄。」

动机拆解：

1. **沉浸不破功**——HTML 浮层的字体渲染、DPI、动画时序永远和 WebGL 世界差半拍，一出现就「出戏」；
2. **光照/材质一致性**——3D UI 吃同一套光照与后期，自动融入美术；
3. **输入设备无关**——3D 交互点天然同时响应车撞、鼠标、手柄射线，HTML 按钮做不到「开车撞它」；
4. **留白的诚实**：Bruno 并非原教旨主义。地图、设置、成就、留言等**面板类 UI 仍是 HTML 浮层**（页面抓取可见完整 DOM 文本），2019 移动端也妥协过虚拟摇杆。他的真实原则是「**内容层 100% in-world，工具层允许 HTML**」——这个分界线比「全 3D」口号更值得抄。DOM 里保留完整文本还顺手解决了 SEO 与可抓取性（本次调研能全文抓到站内文案就是证明）。

### 6.4 字体与 2D 视觉

- 标题 [Amatic SC](https://fonts.google.com/specimen/Amatic+SC)（手写感、玩具感），正文 [Nunito](https://fonts.google.com/specimen/Nunito)（圆体、亲和）——与圆角低多边形世界严格同调；
- UI 图标做成贴纸/木牌质感，成就奖励直接用车漆皮肤渲染图展示。

## 7. 音效与反馈

### 7.1 Bruno 的声音观（原文立场）

「从我做 web 起就觉得行业对 sound design 不够重视。声音是传递情绪最强的手段之一——想象没有配乐的电影。**除了氛围，声音还是强大的 UX 工具：提供线索、反馈与清晰度。**」（Awwwards 案例）

### 7.2 2019：一个人的土法音效

- 碰撞声引擎：物理碰撞→检测速度→从**同类多样本池随机抽取**→按速度调音量+随机微调 playback rate——保证「同一面墙撞两次听起来不一样」；
- **同时发声上限**，防止推倒一片砖墙时「耳朵流血」；
- 引擎声为循环采样按油门变速；
- 开场「纸张展开」音效配合世界弹出动画；
- 技术上全部基于 Howler.js 的速率控制。

### 7.3 2025：分层声景 + 委托创作

| 层 | 内容 |
|----|------|
| 音乐层 | 委托作曲家 Kounine 定制 3 首曲目（「平静中带一点冒险感」），上线后转 CC0 开源 |
| 环境层 | 鸟、蟋蟀、浪、叶间风、雷——随天气系统联动 |
| 物件层 | 铁砧、烤炉、篝火、保龄球瓶、爆炸箱、赛道元素——**全部空间化**（声源在左就从左声道出） |
| 载具层 | 弹簧、液压、引擎、胎噪、boost、喇叭——车是全站声音最丰富的物体 |
| UI 层 | **只用一个 click 音**，关闭面板时调整播放速率做出「开/关」变体——极简但有语法 |
| 合成层 | 开场音、项目翻页音等复杂音效用 GarageBand 制作 |

### 7.4 可迁移的反馈设计原则

1. **每次输入三通道回应**：视觉（车动/灯亮/痕迹）+ 听觉（引擎/碰撞）+ 世界状态（物体位移）——反馈冗余是「手感」的来源；
2. **随机化是真实感的廉价替身**：多样本 + 速率抖动，比录 50 条音效便宜得多；
3. **UI 音效克制到一个音**，把声音预算全部让给世界——UI 响世界哑是新手最常犯的反向错误；
4. **音频必须有一键静音**（L 键 + 世界内按钮 + 设置面板三处入口），且默认音量留白给环境声。

5. **透明人设的复利**：Medium 案例研究、15 集 devlog（2024-10 至 2026-02）、MIT 开源连 Blender 源文件都给——把「作品」升级成「公开课」，让同行成为自来水。有人用他的代码做了婚礼请柬还上了 HN。
6. **对细节的偏执被感知**：尾灯随刹车亮、标签页 emoji 车会动、法式键盘静默兼容——「我知道多数人看不到，但看到的人会替我讲出去」（Bruno 自述受 Metal Gear 系列小岛秀夫影响）。

### 8.3 HN 舆论场的双面镜（对磊哥的预演）

正面高频词：whimsical、attention to detail、works on mobile、「和孩子一起玩」、「希望 web 多些这种野生创造力」。
负面高频词（每条都是磊哥项目的前车之鉴，详见第 11 章）：加载太久像挂了、CPU 拉满、「作为网站功能糟糕：高操作成本低信息密度」、「需要先有上下文才看得懂」、「canvas-only 无障碍为零」、「well-executed but not groundbreaking」。

## 10. 对「车→机器人 + Start here 漫游地图」设想的 UX 映射

### 10.1 先校准一个事实

Bruno 的车**不会变形**。它的「炫技储备」是物理（撞/跳/翻滚）、液压低趴、六款成就皮肤。「车变机器人」是磊哥设想中的原创增量——这既是机会（Bruno 没做过，有差异化），也是风险（没有已验证的先例，成本与收益都要自己兜底）。

### 10.2 定位差异是一切改造的出发点

| | Bruno Simon | 磊哥 |
|--|------------|------|
| 身份 | 创意开发者/Three.js 布道者 | 汽车智能座舱 × AI 解决方案经理 |
| 网站与能力的关系 | **网站本身就是产品能力的直接证据**（做 3D 网站的人用 3D 网站求职，逻辑自洽） | 网站是**信用索引**，3D 是「懂座舱 HMI/3D 渲染选型」的**佐证之一**，不是全部 |
| 访客耐心 | 同行/粉丝愿意玩 10 分钟 | 猎头/主机厂高管可能只给 60 秒 |
| 结论 | 可以让所有人开车找内容 | **必须双轨**：3D 惊艳层 + 60 秒直达信息层 |

| 5 | 「内容 in-world、工具层 HTML」分界线 | 项目展板做 3D，设置/简历下载/联系方式用 HTML 面板 + 完整 DOM 文本保 SEO |
| 6 | 四级救济（Unstuck/Respawn/Reset/地图） | 全套照搬，开放世界的安全网没有省略空间 |
| 7 | 服务器可选、离线可玩的降级架构 | GitHub Pages 静态托管天然契合：排行榜/留言等一律做成 progressive enhancement |
| 8 | UI 单 click 音 + 世界层空间化声景 + 三处静音入口 | 照抄原则，音量默认克制 |
| 9 | 制作复盘文章/devlog | 3D 站上线后必配一篇「选型与性能优化复盘」——对解决方案经理，**复盘文比 demo 本身更能证明专业判断** |

### 10.4 需要改造的部分（有观点）

**A. 车→机器人变形：把「炫技」升格为「叙事」才值得做。**

- 单纯变形动画是一次性烟花：第二次看就没了，且骨骼绑定 + 变形状态机 + 两套操控模式的成本极高（这是 Bruno 用液压和皮肤而不是变形的原因——**表演性自由度要选边际成本低的**）。
- 建议将变形绑定到**职业叙事**上：**车 = 智能座舱载体，机器人 = AI 助手的具身化**。车形态负责「漫游/浏览」（座舱视角），变形为机器人时进入「讲解/对话」模式（AI 解决方案视角）——变形不再是炫技，而是「汽车智能座舱 × AI」定位的**动词化表达**。每次进入项目展区自动变形讲解，离开变回车，变形就有了语法功能（模式切换信号），可重复消费。
- MVP 降级方案：若整车变形超预算，先做「局部变形」——车顶展开机械臂/屏幕做讲解姿态，保留叙事完整性，成本砍半。

**B. "Start here" 必须比 Bruno 的 Start 多做一件事：给逃生门。**

推荐首屏三选一结构：`[Start here →3D 世界]`（主 CTA）+ `[60 秒了解王磊 →传统页]`（次 CTA）+ 自动检测低端设备/弱网时的温和劝退提示。HN 已经替我们做过用户测试：没有上下文的访客在纯 3D 入口前会直接流失。

**C. 分区映射：14 区砍到 5 区起步。**

| Bruno 区 | 磊哥对应区 | 内容 |
|----------|-----------|------|
| Landing | 出生点·车库 | 变形首秀 + 姓名可撞物 + 操作教学 |
| Projects | 座舱作品区 | 3D 车模 Configurator（已有调研）、HMI 案例展板（脱敏） |
| Lab | AI Lab | TTS 座舱可视化等 demo（已有调研）、可交互实验 |
| Career | 履历区 | 时间线做成一条「测试跑道」，里程碑立牌 |
| Social/Contact | 联络站 | 名片、LinkedIn/GitHub 图腾（可撞但链接可点，照抄） |
| Circuit/成就/Whispers | **一期全部砍掉** | 留存钩子对求职站 ROI 低，二期视流量再说 |

**D. 信息效率红线**：从 "Start here" 点击到看到第一个真实作品 ≤ 90 秒（Bruno 世界里纯漫游到 Projects 也在这个量级，但他允许用户迷路，磊哥不允许）。做法：出生点即可望见作品区地标 + 一条不分叉的主路。

**E. 性能预算对齐已有调研**：GitHub Pages 静态托管、首包 < 5MB（Bruno 2019 全站 2.8MB 证明可行）、移动端自动降质、必须有 WebGL 兜底（WebGPU 移动覆盖仍不足）。

### 10.5 一句话裁决

> 抄 Bruno 的**引导语法、空间语法、降级架构**；不抄他的**内容承载策略**——他的世界本身是内容，磊哥的世界只是内容的展厅；变形机器人若做，必须做成「座舱×AI」定位的叙事装置，而非开场烟花。

## 11. 反模式与风险

每条均给出 Bruno 站的实证 + 磊哥项目的规避策略。

| # | 反模式 | Bruno 站实证 | 规避策略 |
|---|--------|------------|---------|
| 1 | **加载即劝退** | HN：「加载太久，我以为坏了，关了标签页」「显示加载完成后又冻结 30 秒」（iOS shader 编译） | 首包分层加载（先出生点后远景）；loader 带文字/百分比双锚点；Start here 点击后才拉大资产，把等待藏进用户主动行为之后；目标：可交互 < 5 秒（快网桌面） |
| 2 | **diegetic loader 无冗余提示** | 「circle loaded and then nothing」——世界内加载环被当成装饰 | 世界内动画 + 屏幕角落传统进度文本并存 |
| 3 | **常驻渲染循环烧 CPU/GPU** | HN：「M3 MacBook CPU 接近 100%」「风扇起飞」 | 页面失焦暂停渲染；静止时降帧或按需渲染；提供画质档位（Bruno 有 Low 档，可抄） |
| 4 | **无跳过出口 / 上下文缺失** | HN：「随便搜进来的人根本不知道这是什么」 | 首屏双 CTA（见 10.4-B）；3D 内任意位置提供「切换传统版」常驻按钮 |
| 5 | **信息效率黑洞** | HN：「high effort for low signal」「作为主页糟糕透顶，Microsoft Bob 的失败是有原因的」 | 双轨制 + 90 秒作品红线 + 简历 PDF 一键直达（不进 3D 也能拿到） |
| 6 | **可达性归零** | HN：「canvas-only，几乎纯视觉，无障碍无解」 | 传统版即无障碍版：语义化 HTML、键盘可达、alt 完备；3D 版明示 aria 提示指向传统版 |
| 7 | **移动端输入冲突/崩溃** | HN：「单指拖动频繁触发 iOS 长按菜单」「手机上卡顿掉帧」 | `touch-action: none` + 长按抑制；触屏自动降质预设（抄 2025 做法）；低端机直接建议传统版 |
| 8 | **浏览器兼容玄学** | HN：Safari/Firefox 首次加载黑屏、刷新后才好；2022 帖 iOS 完全打不开 | WebGPU→WebGL 双兜底（抄 TSL 思路或直接用 WebGL）；加载失败超时自动跳传统版而非死等 |
| 9 | **滚动劫持**（模仿者常见病，Bruno 本尊反而没有） | Bruno 干脆取消了滚动这个概念，页面无滚动条，不存在劫持 | 若做「滚动推进 3D 动画」的首页变体，必须保留原生滚动手感 + 提供跳过；否则学 Bruno 直接砍掉滚动 |
| 10 | **服务器依赖导致体验腐坏** | 正面案例：抓取当日排行榜/留言服务器离线，站内显式提示且核心体验零损伤 | 一切动态功能 progressive enhancement；静态托管下天然免疫 |
| 11 | **技术演示的时效性腐坏（bitrot）** | HN：「这类站点火一阵，然后技术过时、站点失修、再也没人提」 | 锁依赖版本 + 每年一次回归检查写进维护计划；3D 站挂在 Lab 子路径，主站信用不押注在它身上 |
| 12 | **把「别人夸细节」误读为「必须堆细节」** | Bruno 的细节（尾灯/emoji 标题/法式键盘）成本极低但记忆度极高 | 选 3 个「低成本高谈资」细节做深（如：喇叭声是真车录音、机器人待机小动作、车牌彩蛋），拒绝面面俱到 |
| 13 | **一次性烟花陷阱** | 2019 平均停留 54 秒——惊艳≠深度使用 | 接受「多数人只看 60 秒」的现实设计首因效应；深度内容放传统层，3D 层专职制造那 60 秒 |
