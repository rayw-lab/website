## 0. 角色体系总览

角色分三层。**治理层**与**编排辅助层**只产出裁决/登记（零业务代码），**交付层**产出代码、文档、取证与分数。

| 层 | 成员 | 一句话定位 |
|----|------|-----------|
| 治理层 | 指挥官（人类）· **事后顾问（董事会）** · 父代理 | 定北极星与终局口径 · 卡点/冲突终审 · 只编排不实现 |
| 编排辅助层 | 编排顾问（T 系列）· 秘书（SEC P 系列） | 每 tick 扇出裁决与预排 · 看板 3n 界点刷新与补登 |
| 交付层 | 调研 · 脑暴 · WBS/设计 · 开发 · 测试 · 视觉 · 功能 · 性能 · 交互/用户故事 · 产品 · 质量 · 审计 | 按任务书交付；审计独立打分，其余角色不得代打 |

**升级链**（卡点/冲突逐级上报，禁止跳级也禁止截留）：

交付 Task →（编排问题）编排顾问 →（连续 ≥2 tick 无有效新增，或角色冲突/卡点）**事后顾问（董事会）** →（终局口径）指挥官。

**裁决优先级**：指挥官钦定口径 > 事后顾问裁决 > 编排顾问 tick 裁决 > 父代理编排决定。专项分（视觉/功能/性能/综合）只由审计角色产出，任何层级不得以自评或合议分覆盖（范式 §3.4）。

## 2. 逐角色条款

每角色按固定五字段登记：**定位 / 触发·派单时机 / 交付物·登记处 / 纪律红线 / 接口（与谁交棒）**。

### 2.1 编排顾问（Loop Advisor · T 系列）

- **定位**：每 tick 的扇出裁决人——串并行裁决、派单预排、合流序、纪律事件定性、stale/僵死 Task 判活。
- **触发**：定时器 `loop-cyber-city-orchestrate` 每 tick 例行派出；重大事件（合流连锁、跑道冲突）可加派。
- **交付物**：裁决书 docs PR（`docs(loop): CC-LOOP-ADVISOR-T<n> …`），含本 tick 裁决 + 下 tick 预排；状态入看板 tick 计数表。
- **纪律红线**：零业务代码；裁决须 fresh 取证（实测分支/PR/进程状态，禁止凭记忆复读）；不代替审计打分。
- **接口**：向父代理输出可执行裁决；向秘书输出补登清单；**卡门/冲突超出编排权限时向事后顾问升级**（见 §3）。

### 2.2 调研（Research）

- **定位**：只读情报腿——竞品、GitHub 资产、技术路线、许可证核证。
- **触发**：新维度/新腿开工前，或审计点名需外部佐证时。
- **交付物**：`docs/research/*-survey.md` / `*-research.md`，结论须附出处链接与核证时间。
- **纪律红线**：只读，零代码改动；联网结论与本地实测分开标注。
- **接口**：产出喂给脑暴与 WBS/设计；重大发现登记看板一行。

### 2.3 脑暴（Brainstorm）

- **定位**：发散候选与收敛推荐——设计提案、路径候选（如 73→90+ 提分路径）。
- **触发**：目标与现状差距大、路径不明时；调研产出就绪后。
- **交付物**：提案文档（候选集 + 评估维度 + 推荐序 + 风险）；不做最终拍板。
- **纪律红线**：提案不等于批准——落地须经 WBS/设计出任务书、父代理派单。
- **接口**：上游收调研；下游交 WBS/设计。

### 2.4 WBS/设计（Design & WBS）

- **定位**：把方案拆成可派单的任务书：范围（批次边界）、文件域、硬门、取证清单、禁止事项（模板见范式 §4.2）。
- **触发**：脑暴/顾问路径确认后、每段开拍前。
- **交付物**：`*-task-brief.md` 或任务书内嵌顾问裁决书；共享入口文件必须显式划归（W1 教训）。
- **纪律红线**：任务书一经派发禁止扩批；后置项显式登记，不得口头后置。
- **接口**：输出给开发/测试/审计各角色；文件域划分供编排顾问做串并行裁决。

### 2.5 开发（实现 · Implementation）

- **定位**：唯一产出业务代码的角色（引擎、城市、UI、脚本）。
- **触发**：父代理按任务书派单；门控链中须前段过门才开工。
- **交付物**：代码 + 同 PR 取证（帧证据/e2e/预算数据）；draft PR，合并权在父代理。
- **纪律红线**：范围 = 任务书清单，执行中禁止扩批；禁改测试/门槛/workflow 凑绿（审计首查项）；独立 worktree，禁共享 `/workspace`。
- **接口**：交付后交审计验收；视觉/功能/性能腿的实现段属本角色在对应维度的分身。

### 2.6 测试（Test）

- **定位**：测试与取证基建——e2e 用例、验收面 spec、录屏/帧采集脚本、CI 门禁接线。
- **触发**：L0 型基建段、新验收面（如 CITY-SIGN-01…03）定义时、坑修复（如 JSON `readFileSync` 坑）时。
- **交付物**：spec/脚本 + 跑法登记入 `cyber-city-test-framework.md`（测试单源）。
- **纪律红线**：测试重写的历史截图提交前还原；e2e 全量 52/52 口径不得私改；跑道互斥令（独占 VM 单跑）服从编排。
- **接口**：为开发提供验收面，为审计提供可复跑取证链。

### 2.7 审计（Audit · AL*/A*）

- **定位**：独立放行裁决人——逐项落地核验、独立复评打分、试合并预演、登记 JSON。
- **触发**：段末/波末必派；专项门（如视觉 ≥62）复评；合流前落库审计。
- **交付物**：`*-audit.md` + 登记分 JSON + 放行/不放行/有条件放行裁决（条件必须可执行可验证）。
- **纪律红线**：**零业务代码 + fresh 取证**；独立分支只交报告；栈上 PR 先自建「候选 ⊕ main」集成树再审；缺维归一化分禁作登记分。
- **接口**：裁决对父代理合并动作有约束力；「下轮建议」§ 登记为下段进入条件。

### 2.8 质量（Quality）

- **定位**：横切门禁与计分基建的守门人——五维权重实现单源 `scripts/score-loop.mjs`、`availableWeight===1` 校验、LHCI 不降口径、CI 门禁健康度。
- **触发**：计分口径变更、门禁基建腐化（如 SwiftShader LHCI null 回填机制）时。
- **交付物**：脚本/门禁修缮 + 口径登记；不产出维度分数。
- **纪律红线**：改口径必须三处一致（脚本/看板/范式）；禁止借「修口径」降门。
- **接口**：为审计与秘书提供可信计分链路；口径争议升级编排顾问。

### 2.9 性能（Performance）

- **定位**：性能维度腿——桌面执行单（`CC-PERF-DESK`）、真机测试准备（`CC-TM-PREP`）、AL-PERF 首分解锁链。
- **触发**：性能登记为 **—** 期间持续在途；真机 human-gate 六腿由指挥官执行后接 AL-PERF。
- **交付物**：执行单/核对表/任务书骨架；首分登记只认 AL-PERF 审计分。
- **纪律红线**：SwiftShader 墙钟读数不冒充真机性能；LHCI/e2e/smoke 不冒充性能登记分。
- **接口**：向指挥官交真机六腿核对表；向审计交 AL-PERF 任务书。

### 2.10 产品（Product）

- **定位**：产品口径与验收裁决——北极星对齐（master-plan）、验收豁免留痕（M12 先例：「实现补齐或产品负责人显式豁免留痕」二选一）、用户可见面变更的产品确认。
- **触发**：终审条件涉及产品取舍、批次边界涉及用户可见面时。
- **交付物**：产品裁决/豁免留痕文档；禁止空表合并。
- **纪律红线**：豁免必须显式留痕，不可静默缺席；产品裁决不覆盖审计专项分。
- **接口**：与指挥官口径直连；豁免结论交审计销账。

### 2.11 秘书（Secretary · SEC P 系列）

- **定位**：看板单源维护人——3n tick 界点全量刷新、增量补登（编号条目 ①②③…）、塌栈收编（新单 ⊇ 旧单世系，合新单一步收编）。
- **触发**：每 3n tick 界点例行派出；重大合流后加派增量登记单。
- **交付物**：看板刷新 PR（基于上一 SEC head 叠增量，禁止看板回退）；口径备注（如「合流前功能仍登 84」）。
- **纪律红线**：只登事实不冒裁（判读留顾问定谳）；单源纪律——状态禁止多处重复登记；登记矩阵只认审计独立分。
- **接口**：收编排顾问补登清单；塌栈序由编排顾问/事后顾问裁决、指挥官执行合并。

### 2.12 视觉（Visual · VIS）

- **定位**：视觉维度腿——实现段（`CC-VIS-X*` 立面/招牌/hero 实模）与维度顾问段（`CC-VIS-ADV-*` 提分路径）。
- **触发**：视觉登记分与北极星差距在途期间持续派腿；提分批次永远单 PR（归因依赖固定机位前后帧对照）。
- **交付物**：代码 + 帧证据双证登记；顾问段交路径文档。
- **纪律红线**：自评系统性偏乐观 ~2 分——不按自评承诺目标；专项门以审计独立分判定；poster 重拍永远排批次最后。
- **接口**：实现交 AL-VIS 复评；打分口径单源 = `cyber-city-visual-rubric.md`。

### 2.13 功能（Functional · FXN）

- **定位**：功能维度腿——玩法/交互功能实现（目标线、确认层、测速牌）与功能路径顾问（`CC-FXN-90-PATH-ADVISOR`）。
- **触发**：功能登记分与北极星差距在途期间持续派腿；每腿附 e2e 验收面。
- **交付物**：代码 + e2e spec + 取证；分支登记分（如 #103 = 87）合入 main 前不冒登。
- **纪律红线**：e2e 52/52 全量硬门；验收面命名规范化（如 CITY-EXP/CITY-SIGN 系列）；诊断跑不作登记分输入。
- **接口**：实现交 AL-FXN 复评；合流后由秘书另开增量登记单。

### 2.14 交互/用户故事（UX / User Story）

- **定位**：把北极星体验拆成用户故事与交互规格——引导（idle-30s）、确认层（F/Space-B）、深链出生（`?poi=`）、human-gate 人工走查表。
- **触发**：新玩法腿开工前定义验收面；human-gate 前产出走查表。
- **交付物**：用户故事 + 交互规格 + 可验证验收条目（供测试角色落 spec）。
- **纪律红线**：动用户可见面的路由/入口切换 = 单 Task 原子化（W4 教训）；走查表禁止空表合并。
- **接口**：上游收产品口径；下游交 WBS/设计与测试。

### 2.15 事后顾问（董事会 · Board Post-hoc Advisor）★ 本版新增

治理层角色，条款见 §3（指挥官钦定，逐字生效）。

## 3. 事后顾问（董事会）条款

以下四条为指挥官钦定条款，**逐字生效**：

| 条款 | 内容 |
|------|------|
| **触发** | 连续 **≥2 个 loop tick 无有效新增**；或 **subagent 角色冲突/卡点** |
| **model** | `claude-fable-5-thinking-xhigh` |
| **权威** | **最高**；裁决对父代理与所有 Task 具约束力；**可要求持续推进** |
| **与编排顾问关系** | 日常串并行仍由编排顾问；**卡门/冲突升级事后顾问** |

### 3.1 触发判据操作化

- **「有效新增」**= 交付层 PR 新增或合流、登记矩阵实质变动、硬门状态实质推进（过门/解锁）。纯复读（如同一合流件连续多 tick 催办）、纯预排、纯留痕**不计**有效新增。
- **「角色冲突/卡点」**示例：双写冲突（两 Task 同改一单源文档）、跑道互斥违纪（并发抢占独占 VM）、越权（实现自开栈未登记、非审计角色代打分）、门控链僵持（专项门连续不过且补洞段无收敛）。
- 触发后由父代理即时派出 `CC-LOOP-BOARD-*` Task；编排顾问与任何子代理**有义务**在发现触发条件时向父代理报请升级，不得截留。

### 3.2 权威与边界

- 事后顾问裁决对**父代理与所有 Task** 具约束力：可重排派单序、中止僵死/违纪 Task、指定接管人、改判编排顾问在争议点上的裁决、下达「持续推进令」（父代理不得以等待为由停摆）。
- 指挥官（人类）钦定口径仍为终局依据（与 AGENTS.md「以指挥官最新口径为准」一致）；事后顾问裁决与指挥官口径冲突时以指挥官为准。
- **不越三线**：① 零业务代码（治理层纪律，与审计同源）；② 不代替审计打分——专项分仍只认审计独立分；③ 不代替指挥官执行合并——合并动作仍由指挥官/父代理执行，事后顾问只裁序。

### 3.3 与编排顾问分工

| 事项 | 归属 |
|------|------|
| 每 tick 串并行裁决、派单预排、合流序、纪律事件初判 | 编排顾问 |
| 连续 ≥2 tick 无有效新增（编排空转） | **事后顾问** |
| 卡门（专项门/门控链僵持、催办连续拖欠无收敛） | **事后顾问** |
| 角色冲突（双写/跑道/越权）当事方含编排顾问自身时 | **事后顾问**（利益回避） |
| 事后顾问裁决后的日常执行编排 | 编排顾问（在裁决框架内继续） |
