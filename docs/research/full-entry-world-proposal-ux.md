## 0. 摘要（先读这 6 行）

1. 用户愿景没有变过：「首页打开就是 3D 炫技车，Start here 后地图漫游」——即 folio-2019 的开场语法。先前 Hybrid 方案把 3D 收编为内页展项，保住了门禁、丢掉了愿景的**第一句话**。
2. 现行 `/world-spike/` 被否定的根因不是「3D 不够多」，而是**它从头到尾是一件工程验证物被当成了体验交付物**：三重门入口、灰盒美术、工程仪表 HUD、自我矮化文案（第 5 章逐条拆解）。
3. 本文给三条路线：A Full Entry（`/` = 全屏 3D 世界）、B 双模式（`/world` 默认 + HTML `/home`）、C 渐进（首页 WebGPU Hero 全屏炫技车 + 一键「驶入世界」无缝扩展）。
4. **推荐路线 C**：它逐字兑现用户愿景（打开=炫技车、Start here=漫游），首屏预算只有「一辆车 + 一个舞台」而非整个世界，且保留了通往 A/B 的演进通道（第 3 章）。
5. 代价必须先说破：无论选哪条，PRD 的「首页四项 Lighthouse ≥95、首屏 <200KB、LCP 非 canvas」门禁都**必须正式修订而非默默违反**——这是与先前决策的正面推翻，属于用户必须拍板的事项（决策问题 Q1）。
6. 猎头/移动端/SEO 三类风险全部有既定缓解件（跳过出口、2D 等距地图、DOM 文本层），Bruno 两代站 + HN 188 条评论已替我们做完用户测试，照单抓药即可（第 4 章）。

## 1. folio-2019 vs folio-2025 首屏体验对比

用户要的「打开就炫技」在 Bruno 两代站里有两种截然不同的答卷。源码坐标以 `vendor/` 内两仓库为准（拆解详见 `bruno-simon-folio-source-teardown.md` §7）。

### 1.1 对照表

| 维度 | folio-2019（Start 按钮流） | folio-2025（Intro 圆环 + Reveal 流） |
|------|---------------------------|-------------------------------------|
| 入场门 | **显式 Start 按钮**：base64 内嵌 "Loading" 图零请求秒显，加载完淡出换 "Start"（`World/index.js` L186-211）；把车开进区域 / 点击 / Enter 三种手势均可触发 | **无门**：加载进度画成地面 3D 发光圆环（`Intro.js` RingGeometry + `atan` 极坐标 shader，按角度 discard），圆环走完任意驾驶键 / 点击出生圈即入世——**驾驶键本身就是开始键**（`Reveal.js` L139-141） |
| 加载可视化 | 出生点脚下矩形区域的地面边框当进度条（`uLoadProgress`） | 圆环 `smoothedProgress` 每帧向真实进度指数缓动（L311-314），进度跳变也丝滑 |
| Reveal 揭示 | Start 点击 600ms 后 `reveal.go()`：matcap 全局渐显 3s + 车从天而降落地弹跳两下（刻意设计：「第一眼就知道有物理」） | 三步状态机：step0 圆环缩没（power4.in 1.5s）→ 网格地板亮起 → reveal 半径 0→3.5m **圆形擦除**（材质级 discard，世界只「存在」出生点一圈）→ 首次输入后半径撑开揭示全图 |
| 重系统构建时机 | **Start 之后**才建物理/车/全部 Section——加载页只有地板和两张 base64 图 | 加载期间全部建好（wasm 与 GLB 并行），Start 手势只做揭示 |
| 音频解锁 | Start 点击（按钮存在的第一技术原因就是浏览器自动播放策略） | 首次输入（step 0→1） |
| 教学 | 说明直接写在地上，物理实体方向键可撞 | 浮空提示牌按输入设备热切换四套贴图（键鼠/Xbox/PS/触屏） |
| 已验证的失败模式 | 按钮=明确心智锚，无「不知道这是进度条」问题；但多一次点击 | HN 实测流失：「circle loaded and then nothing」——diegetic loader 不被识别为加载器；iOS shader 编译假死 30s |

### 1.2 对本站的启示

- **用户愿景对应的是 2019 语法**：先给一个「看得懂、够惊艳」的首屏静物（当年是即将落下的世界，本站是炫技车），Start 按钮承担期望设定 + 音频解锁 + 重资产加载的三合一仪式。2025 的无门直入更「酷」，但它把最大流失点（加载谷）完全暴露，Bruno 有粉丝耐心兜底，王磊的猎头访客没有。
- **可以偷 2025 的揭示技法**：reveal 半径圆形擦除（「世界从车周围长出来」）恰好是路线 C「一键驶入世界」的理想转场——车不动，世界向外生长，无路由跳转、无黑屏、无灰盒感。
- **两代共同点**：首屏永远有一个「已经在动的 3D 物体」压阵（2019 的地板/2025 的圆环），加载从不以白屏或 HTML 进度条示人。这正是现行 `/world-spike/` poster 壳最欠缺的一课。

## 2. 三条路线对比

先定义清楚，再上表。

- **A. Full Entry**：`/` 直接就是全屏 3D 世界（folio-2025 式）。打开即出生在试验场，HTML 内容全部以 overlay / 独立内容页存在，没有「HTML 首页」这个概念。
- **B. 双模式**：`/`（或 `/world`）默认进世界，HTML 五区块整体迁到 `/home` 作为平行入口；两边互设显眼切换口，SEO/猎头链接可直接指 `/home`。
- **C. 渐进**：`/` 打开就是**全屏 WebGPU Hero**——炫技车即刻在场（转台、灯光、车漆流转，或待机小动作），首屏只加载「车 + 舞台」；点「Start here · 驶入世界」后**同一 canvas 内**世界围绕车揭示（2025 式 reveal 擦除），无路由跳转、无第二次加载屏、无灰盒感；世界分区资产在用户玩车的掩护下流式加载。HTML 内容层保留为 canvas 之下/之外的可达出口（形态见 Q3）。

| 维度 | A. Full Entry | B. 双模式 | C. 渐进（推荐） |
|------|--------------|-----------|----------------|
| 用户愿景兑现度 | 超额兑现（打开即世界，比愿景更激进——愿景其实是「先车后世界」两拍） | 兑现，但「默认进世界」与「猎头 30 秒」直接对赌 | **逐字兑现**：打开=炫技车（第一拍），Start here=漫游（第二拍），与愿景的两拍结构一一对应 |
| 首屏冲击 vs 加载风险 | 冲击最大、风险也最大：首包=整个世界（Bruno 级数 MB~十几 MB），复现 HN「加载太久以为坏了」的概率最高 | 同 A（世界侧）；`/home` 无风险但没人看 | 首屏只要车模（现有 CarConcept 3.4MB，可出 ≤1.5MB 减面首发版先上、高清版后台替换）+ 程序化舞台，**可交互时间与现 Hero 同量级**；世界首包延迟到 Start here 之后，等待被「已经在玩车」掩盖 |
| 猎头/SEO/无障碍 | 最差：全靠 overlay 与 DOM 文本层撑，og/首屏文案/10 秒定位全部重做 | `/home` 全保：SEO 主战场迁过去，代价是权重分裂 + 「哪个是官网」的心智混乱 | 中：`/` 的 DOM 保留定位语 + 双 CTA 文本层（canvas 之上/之下），内容页 HTML 不动；LCP 变为 poster/canvas 需修订门禁 |
| Lighthouse 门禁冲突 | 全面冲突，C-2/C-3/NFR-P3 三条全废 | `/` 侧同 A；`/home` 达标但不再是入口 | 冲突可控：首屏 <200KB 必破（车模在关键路径），但 LCP 可仍锚定 poster（车模渐进替换 poster 的手法 HOME-07 已有）；需修订而非全废 |
| 工程改造量 | 最大：世界必须一步到位建成「值得当首页」的完成度（美术、POI、内容映射全齐）才敢上线 | 世界侧同 A + 路由/SEO 迁移工程 | **最小可上线单元清晰**：第一步只需「Hero 车全屏化 + Start here + reveal 擦除进灰盒改造版世界」；世界美术可迭代追加，车先炫起来 |
| 移动端 | 默认进世界=默认吃最大风险面（Bruno 移动端 stutter/iOS 冻结实录） | 同 A | 首屏车舞台移动端可跑（配置器同资产已验证）；「驶入世界」在低配设备上可劝导降级，炫技第一拍不受损 |
| 失败回退 | 回退=重做入口，成本最高 | 回退=改默认路由，中 | 回退=Start here 按钮指回独立世界页，首页仍是全屏炫技车——**第一拍永远保得住** |
| 对应 Bruno 原型 | folio-2025 | 无直接原型（Bruno 从未做过双入口） | folio-2019（静物 + Start 两拍结构），揭示技法借 2025 |

## 3. 对王磊站点的推荐路线与理由

**推荐 C（渐进），并把它明确为「通往 A 的第一阶段」而非终点。**

理由收束为四条：

1. **它是用户愿景的直译，不是折中**。愿景原文「首页打开就是 3D 炫技车，Start here 后地图漫游」本身就是两拍结构——C 的「Hero 全屏车 + 一键驶入」与之逐字对应。A 反而改写了愿景（去掉了第一拍），B 只是把 Hybrid 的门从「点进 Lab」换成「点去 /home」，割裂感换了个方向仍在。
2. **座舱试验场主题在 C 下叙事最顺**。「打开是一辆概念车在标定舞台上待命 → 按下 Start here → 试验场围绕车揭示、驶出舞台开始场地试驾」——这是真实试验场的流程（静态检查 → 动态测试），车是主角、世界是考场，与「个人专业信用系统 = 用可验证的测试证明能力」的定位同构。A 的「出生在世界里」反而弱化了车的首因地位。
3. **风险预算花在刀刃上**。三条路线里只有 C 把「最贵的东西」（整世界的加载与美术完成度）挪出了首屏关键路径：第一拍用已验证的资产（CarConcept + 配置器渲染管线，帧率/体积数据 `world-spike-log.md` §3-4 齐备）就能上线炫技；第二拍的世界可以从灰盒改造版起步、按分区逐步换装美术，每一步都有可发布状态。A/B 则要求世界一次成型。
4. **演进通道单向兼容**。C 跑通且数据好（Start here 点击率、进入后停留、内容转化），把 reveal 自动化即得 A（打开直接播 reveal = Full Entry）；数据差，第一拍独立成立。B 则是死路——一旦做了 `/home`，回收它比不建它贵。

关键执行红线（C 之所以「无灰盒感」的三个必须）：**同一辆车**（Hero 舞台的车 = 驶入世界开的车 = 配置器的车，车漆状态互通）、**同一个 canvas**（reveal 擦除揭示世界，禁止路由跳转/第二加载屏/poster 二次覆盖）、**世界即刻有可看的东西**（出生视野内必须有「王磊」可撞立体字 + 第一个 POI 地标，哪怕远处仍在流式加载）。

## 4. 猎头 / 移动端 / SEO 风险与缓解

Bruno 站的 HN 舆情（777 分 / 188 评论）已替我们做完压力测试，每条风险都有实证与既定缓解件：

| 风险 | 实证 | 缓解（C 路线下的具体形态） |
|------|------|--------------------------|
| 猎头 60 秒内拿不到信息即流失 | HN：「如果只是想找信息，它很折磨」「terrible as a homepage」 | ① 首屏 DOM 层常驻定位语（「王磊｜汽车智能座舱与 AI 解决方案经理」）+ 「60 秒了解王磊 →」次 CTA，与 Start here 并列——**跳过出口从第 0 秒可点**；② 世界内右上角常驻「退出 3D」+ ESC 菜单「招聘方速览 → /work/」；③ 简历 PDF 不进 3D 也能一键拿到。任一出口失效算 P0 bug（沿用 adaptation §3.3 清单全套） |
| 移动端卡顿/冻结/输入冲突 | HN：iOS「加载完冻结 30s」（shader 编译）、单指拖动触发长按菜单 | ① 第一拍（车舞台）移动端全量提供——配置器同管线已验证；② 「驶入世界」在触屏窄屏/低配（`saveData`、无 WebGL2、`reduced-motion`）设备上呈现 **2D 等距地图**（SVG 插画，六分区可点、键盘可达）替代 3D 漫游，并留「仍要进入 3D（实验性）」opt-in；③ 摇杆沿用 spike 已验证实现（转向曲线与基座锚点两处改进项照单修）；④ shader 预热塞进 Start here 后的 reveal 时间窗，`touch-action: none` + 长按抑制 |
| SEO/可抓取性/无障碍归零 | HN：「canvas-only 无障碍无解」；Bruno 自己都在 DOM 保留全文（本站 teardown 能全文抓取即证明） | ① 内容页（/work/、/insights/ 等）保持纯 HTML 不动，权重主体不迁移；② `/` 的 title/description/og 与定位语、双 CTA 均为真实 DOM 文本，canvas 只是视觉层；③ `<noscript>` 与降级路径给完整六导航链接；④ 世界内每个 POI 的深内容 = canonical HTML URL（overlay/跳转），无「只在 3D 里才存在」的信息 |
| 加载谷流失（新增，C 的主战场在第二拍） | HN：「circle loaded and then nothing」 | reveal 期间车已可玩（原地油门、鸣笛、换漆），世界分区流式补齐；加载可视化用「圆环 + 文字百分比」双锚点（修正 Bruno 的 diegetic-only 教训） |

## 5. 与现有 /world-spike/ 灰盒的差距：「不行」的根因分析

用户的否定不是审美挑剔，而是精准命中了 spike 的本质——它是 `world-spike-log.md` 定义的**工程验证物**（「Spike 产出默认可丢弃，全部价值在验证结论 + 参数记录」，壳页头注原文），却被摆上了生产站当体验交付物。逐条拆：

| # | 根因 | 现状证据 | 与愿景的落差 |
|---|------|---------|-------------|
| 1 | **三重门入口，愿景是零门** | 首页 HTML 五区块 → 找到 world-spike 链接 → 壳页 poster 覆盖层 → 点「进入试验场」才见 3D | 愿景是「打开就是 3D 炫技车」；现状是炫技藏在第三层门后，且每层门都是静态页面 |
| 2 | **灰盒美术=反炫技** | 地面/环形道是 2048px 程序化画布纹理，锥桶/坡道/轮胎墙全是 primitive 实例（`public/world/` 新增 0 字节——这本是 Spike 门禁的功劳，却成了体验的死刑） | 写实 PBR 的 CarConcept 放在无光影、无氛围、无地平线叙事的灰盒里，反差放大廉价感——车越好，场越假 |
| 3 | **无开场仪式** | 点击进入后直接出现在环形道上，无 diegetic loader、无 reveal 揭示、无落地弹跳、无「撞名字」教学 | Bruno 两代的共同底线（首屏永远有在动的 3D 物件、加载即动画）一条没有 |
| 4 | **HUD 是工程仪表** | 常显「FPS 均值 / 1% low」「锥桶 0/16」「复位 (R)」——这是给 CI 与真机录测看的遥测面板 | 访客读到的潜台词是「这是测试版」；游戏 HUD 应该是速度表 + 目标指引，帧率仪表该藏进 debug 参数 |
| 5 | **文案自我矮化** | 壳页正文写「实验性 DEMO」「技术验证记录见 `docs/research/world-spike-log.md`」 | 把内部免责声明暴露给访客，等于开场先说「别当真」——与炫技的姿态正好相反 |
| 6 | **无内容、无目的地** | 世界里只有环形道 + 16 只锥桶，零 POI、零信息、零「往那边开有东西」的信息气味 | 愿景的后半句是「地图漫游（浏览作品集）」；现状开一圈之后无事可做，54 秒都留不住 |

一句话诊断：**用户否定的不是 Hybrid 里的 3D，而是「3D 被当作附件」这个姿态本身**——入口层级、美术投入、HUD 语言、文案口吻全都在向访客声明「这不是正片」。路线 C 的全部设计（首屏即车、同 canvas 揭示、POI 即刻可见）就是把这六条逐一反转。

## 6. 需用户拍板的 5 个决策问题

| # | 问题 | 选项与默认建议 |
|---|------|---------------|
