## 0. 结论先行

1. **84 的缺口画像**（首登 Pass B 向量）：F3 75 / F6 75 双低洞，F1/F2/F4/F5 85 四维「一步之遥」，F7 95。合成 83.5 → 84。距 90 差 **+6.0 加权分**。
2. **云端封顶定理（本报告核心裁决）**：F1 高段锚「0:15 前说出下一步」与 F2 高段锚「≤100ms 可感知延迟」是**计时类判定**，SwiftShader 禁令（rubric §3.2-5）下云端审计恒锁 85——首登轮已按此口径执行（F1「止于 85」是判例）。于是即使其余五维全部拉满（F3/F4/F5/F6 = 90、F7 = 100），合成 = 89.25 → **89，90 数学上不可达**。**结论：最短合法路径必含一条指挥官真机 S-2 复测增补腿**（合法性先例：首分顾问 §4.1-3——S-2 本就是「指挥官复测口径」，增补证据不改双 Pass 规程、不升脚本版本、不是登记签字 gate）。
3. **需补的维/腿 = 两刀代码 + 两腿取证 + 一轮登记**：
   - 代码刀 1（**CC-FXN-C5**）：G4 目标线 v0 + `idle-30s` 消费（空闲主动引导）→ 主攻 F6 75→90、F3 75→85、F4 自然发现，并给 L7 腿产品面；
   - 代码刀 2（**CC-FXN-C6**）：F 悬挂跳与 Space/B 刹车的专属确认层 + G9 测速牌 → 补齐 F2 最后半价项、给 F3 一个「想再来一次」玩点；
   - 取证腿 1：**L6 单会话 `?quality=2` 七步闭合重取证**——零代码差距（首登已证明 Q2 会话变形+驾驶成立，只缺同会话进站），纯审计侧重跑，解锁 F5 85→90；
   - 取证腿 2：**指挥官真机 S-2 复测**（合流 tip 上执行，录屏 + 每腿 dump + 三问三件套）——一条腿同时解锁 F1「0:15」、F2「≤100ms」、F3「≤3s 恢复/主动要求继续开」、F4「30s 内自然吸引」四个计时触及高段；
   - 登记轮：**CC-AL-FXN-R3** 双 Pass 重打分 + 重写登记 JSON（只改分值与证据，schema/秤不动）。
4. **预计轮次：1 轮实现（C5 ∥ C6 两个并行 PR）+ 1 轮审计登记（内嵌真机增补与 L6/L7 重取证）= 2 轮**。若真机窗口缺席，审计轮如实登记 ~87–88（诚实中间态），90 顺延至真机证据补齐后的 R4 复审（同 commit 只补计时证据，轻量轮）。
5. **目标向量（诊断参考，禁写入登记 JSON）**：F1 90 / F2 90 / F3 90 / F4 90 / F5 90 / F6 90 / F7 95 → 合成 90.5 → 登记 90–91。冗余设计：容任一 15% 维滑落 85 仍 ≥ 89.75 → 90；通过 rubric §2.3 反凑分校验（无 ≤70 维、六维 ≥90）。

### 2.2 云端封顶与真机腿的不可替代性

- **从严口径**（与首登 F1 判例同一纪律）：F1/F2 云端恒 85。其余五维全拉满（F3/F4/F5/F6=90、F7=100）→ 89.25 → **89**。且 F3「≤3s」/F4「30s」高段子句本身含计时，云端从严实际落点约 **87–88**（C5/C6 合流后、无真机的诚实区间）。
- **真机 S-2 一条腿的价值**：+3.25 加权（杠杆 D/E/F/G 的计时部分）——是 84→90 全部增量的近半，且**无代码替代物**。设备与耗时需求极低：桌面 Chrome + 一遍 S-2（约 15 分钟含录屏与 dump 导出），无安卓依赖（那是性能轨的事）。
- **反凑分校验**（rubric §2.3）：目标向量六维 90 + F7 95，无 ≤70 维、≥四维 90，sanity 通过；不存在「某维满分掩护短板」路径。
