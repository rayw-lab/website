## 0. 结论先行

1. **综合 98 的唯一决定轴是视觉**。综合分五维（LHCI `/` 25% + LHCI `/home/` 15% + e2e 20% + 视觉 rubric 25% + smoke3d 15%，**不含功能/性能**）中，四条非视觉轴在 AL-CAM 轮全部实测 100；四轴保 100 时综合 = 75 + 0.25×视觉，**综合 ≥98 ⇔ 视觉 ≥92**（每 +4 视觉 = +1 综合，与 VIS-L8 调研 §0-3 换算一致）。视觉 92 落在 VIS-L8 的 **P2「红线重谈段」**——P1 顶点（85）只能到 96.25，**综合 98 没有绕开视觉 P2 的合法路径**；改秤不是路径（§2.4）。
2. **第一步不是提分，是登记刷新（M0）**。生产登记 **80** 为指挥官口径改登（`acaf28b`，同步进 `AGENTS.md` §4.4「以指挥官最新口径为准」），**无对应 score-loop 实算在档**；最后一次五维齐套实算 = **92.8**（AL-CAM：LHCI 100/100 + e2e 100 + 视觉 71 + smoke 100）。M0 = 当前 tip 五维齐套实跑一轮（预期 ~92.8，诊断值），产出「实算 + `availableWeight===1` + LHCI 来源 commit」证据链；**改登与否归指挥官拍板**，实算证据随下一次 AL 审计轮捎带（看板综合行「功能/性能登记后五维重算」已预留此拍，零新增 Task）。
3. **护轴纪律是综合分的第二工作面**。四条非视觉轴不是「不用管」，是「钉死在 100」。敏感度（一手核验分母）：**smoke3d 单例红 = −5.0 综合，直接使 98 数学不可达**（视觉需求线 112 > 100）＞ lhciRoot 四项均值每 −1 = −0.25（root 回落到 L0 的 97.75 时，视觉需求线从 92 抬到 94.25）＞ e2e 单例红 ≈ −0.27（分母 75）。视觉是全场最贵的分，任何护轴失守都在给最贵的轴加价。
4. **里程碑与视觉轨完全同构**：M0 登记刷新（~92.8）→ M1 = 视觉 P0（73–75 → 综合 93.3–93.8）→ M2 = 视觉 P1（80–85 → 95.0–96.25）→ M3 = 视觉 P2 中途（≥92 → **≥98**）。综合分没有自己的实现面，**不建议新开「综合专项批」**；本调研新增动作仅两条：M0 一行写进下一 AL 任务书 + 审计报告固定输出「综合敏感度行」（§5）。
5. **反通胀重申**：本文全部预计值禁止登记；smoke3d 分母扩充只能以覆盖为动机并经审计核准，禁止以稀释单例敏感度为动机注水（§3.4）；92.8→80 的口径差不允许由任何子代理自行「刷回」——M0 只交实算证据，登记权在指挥官。

## 2. 综合分代数（秤冻结下的硬数学）

### 2.4 改秤不是路径

① 五维口径三处一致（看板口径 = `score-loop.mjs` = 登记文档）是 AL0 以来的审计首查项，改秤是治理事件，须指挥官显式裁决 + 三处同步；② 调低视觉权重或调高已满轴权重属于典型登记通胀——秤为目标服务，不是目标为秤服务；③ 功能/性能是**并列**北极星、不折算进五维（可观测规格 §6.4 冻结、`score-loop.mjs` northStar 块注释明文）——把功能/性能折进综合既稀释视觉需求线又推翻「并列北极星」决策，不在本调研范围。**本调研按秤恒定推演，唯一合法提分面 = 视觉轨 + 护轴。**

## 3. 四条护轴轨（综合分专属工作面）

### 3.1 lhciRoot（25%，现 100，有回潮史）

- **回潮风险源**：视觉批动壳 DOM/HUD 时的 `aria-hidden-focus` 型回归（L0 实锤：HUD 在 `aria-hidden` 容器内含可聚焦元素，采样窗恰逢挂载完成态）与移动端小字号 `font-size` 型回归（formFactor=mobile 判定）。V6 打包批（HUD 装饰化）与 V1 首幕批（壳内景框/提示件）是高危批次。
- **防线（全部已在，引用即可）**：每段放行硬门「LHCI `/` 与 `/home/` 四项逐项不降」+ 3 轮中位数抗抖 + SwiftShader null 时 CI artifact 回填并登记来源 commit（已知坑 #1）。
- **口径注记**：本轴是 localhost/CI 上界口径（基线 §B.6），综合分按此口径冻结计分；线上真机 Lighthouse 是部署后另行校准项，不进综合登记。

### 3.2 lhciHome（15%，现 100，最稳轴）

三轮零波动史。唯一注记：`/home/` LCP 中位 1878ms 高于 `/`（1354ms），首页改版类任务的 LHCI 硬门不可豁免；此外无动作。

### 3.3 e2e（20%，合同 75/15，双重身份）

- **双重身份**：既是综合 20% 轴，又是每段放行硬门与功能/性能两登记轨的共同前置——e2e 红一例，综合 −0.27 只是最小的代价，真正的代价是**全部登记与合流停摆**。
- **现状**：CAR-E2E-01/05 超时修已合 `4c1e37f`，修后 75/75 clean 全绿尚无在档实证——M0 登记刷新轮顺手补上这份实证（本来就是审计硬门）。
- **墙钟预算**：L0 时点 52 例 ≈ 18.4 min；现 75 例含 CITY-PERF-01/02 两条长时殿后用例（900/1200s 上限重标定先例 `d6b1141`），排期按每轮 **25–40 min** 预算（范式坑 #3 的更新值）。
- **合同增长纪律**：每个新 spec 都在抬分母、也在抬 flaky 面——新增用例沿 world 链串行独占拓扑（car-chromium 独占先例），计时断言只做状态序。

### 3.4 smoke3d（15%，分母 3，全场最高单例杠杆）

- **事实**：分母仅 VIS-02/03/04 三例，单例红 = 综合 −5.0 = **98 数学不可达**（§2.2）。三例全部压在首幕挂载链上（canvas 像素统计 / ESC dialog / POI 深链出生）——恰是视觉批全帧变化的误伤高发区。
- **防线**：像素基线更新必须走「经审阅的有意变更」流程（`--update-snapshots` 逐张说明，禁止批量重拍掩盖回归）；TM/V1 等全帧批的任务书须显式写「VIS-01/02 基线经审阅更新，VIS-03/04 像素统计阈值不放宽」。
- **分母治理**：新增 `@smoke3d` 用例会同时改变分子分母，**动机必须是覆盖**（候选：变形链冒烟、驾驶链冒烟——若 M2 段落地新交互面可顺势补），在任务书显式登记并经审计核准；**禁止以稀释单例敏感度为动机注水分母**。现阶段维持 3 例 + 护绿即可。
