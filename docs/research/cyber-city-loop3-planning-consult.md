### A.3 三道门如何并行而不冲突

三道门是 **AND**，不是互相替代：

1. `|自评整数分 - 独立审计整数分|≤5` 是**评分一致性门**，只回答“自评是否可信”。
2. 独立视觉 `≥62` 是**历史安全底线/旧 Tier B 解锁门**，Loop 3 中用于阻止候选倒退到
   Night City 分界线以下；它不是 Loop 3 成功线。
3. 独立视觉 `≥68` 是 **Loop 3 终审硬门**。只有独立审计分可触发，不能用自评分或
   综合 91+ 代替。

| 自评 | 独立审计 | Δ | 判定 |
|-----:|---------:|--:|------|
| 72 | 67 | 5 | 一致性通过、62 底线通过、**68 终门失败** |
| 74 | 68 | 6 | 68 达标、**一致性失败**，须逐维复议，不能放行 |
| 72 | 68 | 4 | 三门同时通过 |
| 64 | 61 | 3 | 一致性通过、**62 底线失败** |

为避免整数四舍五入掩盖边界，审计报告同时登记七维原始加权值与整数值；硬门按 rubric
现行“原始加权后四舍五入”的正式整数分裁决，但原始值用于判断是否值得再开一个 Task。

### A.4 单聚焦 PR 与 stacked PR 例外

默认只接受“前一实现 → 独立审计 → 合入/形成明确集成基线 → 下一实现”的串行链。
stacked PR 只在同时满足下列条件时允许：

1. 下游确实依赖上游未合入的最终像素或 API，且上游 head SHA 已冻结；
2. 文件域基本不重叠，下游不改变上游验收口径；
3. PR base 明确指向上游分支，并在描述中登记 base/head SHA；
4. 上游审计无待修项；任何上游新提交都会使下游证据失效并要求重拍/重跑；
5. 最终审计必须针对 rebased/merge 后 exact integration tree，不能把两张各自绿的 PR
   当作集成树已绿。

Loop 3 中唯一推荐的 stacked 例外是：运行时最终 PR 已审计冻结、父代理仅等待合入时，
`CC-L3-POSTER` 可叠在该冻结 SHA 上提前重拍。ATM 不叠 B2C，B3/B5 不跨中审闸叠加。

## B. Loop 4–5 前瞻草图

### Loop 4：生命感与电影化二选一

进入条件：`CC-AL3` 完成；如果独立视觉已 ≥68，先确认业务是否仍需要继续追分。

- 若 V4 仍最低：主题只开 **B3 飞行光轨/环境生命感**。依赖 CITY-03 配额书面统一、
  Q2 关闭、动态性能证据和 dispose 闭环。
- 若 V5 仍最低：主题只开 **B5 变形运镜**。依赖 reduced-motion 直出、固定 5–10 秒
  视频、驾驶接管镜头不漂。
- 两者可在同一 Loop 先后做，但必须是“实现 → 独立审计 → 再决定另一项”，不得同批。
- 运行时全部冻结后再重拍 poster；若 Loop 3 已重拍而 Loop 4 又改画面，Loop 4 必须承担
  新一轮三面重拍，不得沿用旧 poster。

Loop 4 的目标应是把独立视觉稳定到约 **70–72**，不是预支 Tier C 的 75。

### Loop 5：程序化上限验证与 Tier C 单主题打磨

进入条件：Loop 4 独立审计给出明确最低维，且过去两轮仍有可量化增益。

只选一个主题，不把 Tier C 九项打包：

- **V2/V4 材质密度主题**：近景约 10% 假室内映射窗格 + 少量机器人材质分区；
- **V1 景框主题**：前景桥架/管线剪影 + 静态低云/月轮；
- **V6 HUD 主题**：速度表接线与 SVG 霓虹弧线，顺带销历史观察 F；
- **V3/V5 状态主题**：巡航态色温微移或招牌 stagger，前提是动画配额已有统一口径。

Loop 5 终审除常规硬门外，必须回答一个问题：当前差距主要是“还能靠程序化小件改善”，
还是已经变成“实模楼体、手工道具和烘焙材质密度缺失”。前者可再开一个窄 Loop，后者
停止普通提分 Loop，转 Blender 专项立项。

### C.2 何时停止普通 Loop

满足任一条件即停止追加效果：

1. `CC-AL3` 已同时满足独立视觉 ≥68、`Δ≤5` 和全部工程硬门——Loop 3 目标已完成；
2. 连续两次独立审计原始加权增益都 `<1.0`，或新增件帧内不可见；
3. 主攻维度没有上升，反而靠非目标维抵消；先判定方案失效，不扩批；
4. 任一硬门失败且修复会越出当前 Task 聚焦边界；开修复 Task，不继续视觉 Task；
5. 剩余差距被审计明确归因为实模密度，而非程序化雾、光、构图或证据债务。

综合分已经 91.0，不能把“继续涨综合”作为无限开 Loop 的理由。达到独立视觉 68 后，
除非产品目标升级到 75/85，应优先收口而不是继续堆效果。

### C.3 何时开 Blender/实模专项

**现在不开。** 64→68 仍有 B2 内容化、分层大气和一个受控 B3/B5 的低风险空间。

只有同时满足下列条件才立项：

1. 产品明确把目标从“Loop 3 ≥68”升级到 **≥75 或 HM/85 档**；
2. Loop 4/5 独立审计显示 V4 长期低于 70，且差距稳定指向楼体轮廓、近景道具、材质分区
   与烘焙光照，不是机位、雾或招牌可见性；
3. 连续两轮程序化改动边际收益进入停止线；
4. 先批准一个 hero 楼/街角的资产 spike，单独核算 Blender 源文件、许可台账、
   Draco/KTX2、LOD、Q2/移动端 fallback、world 资产池、加载失败回退与 poster；
5. 专项用独立预算、独立 PR 栈和独立验收，不混进常规视觉 Loop。

如果 spike 在固定主机位没有显著抬升 V2/V4，或破坏 12MB 资产池/真机帧率，则终止实模
扩面；不能因已经建了管线就默认全城换模。

## D. 对父代理编排纪律的 5 条改进建议

1. **先锁 exact tree，再看分。** W0–L2 多次出现分支分叉、报告“假删除”和 CI 工件
   来自相邻 SHA。每次派审计时把 base、candidate、merge-base、预演集成 SHA 写成四元组；
   审计只对该树裁决。
2. **把“一致性门”和“绝对门”拆成两列。** AL2-a 已证明 `Δ2≤5` 不等于独立分达到
   62。看板不得只写“复评通过”，必须分别写自评、独立原始/整数分、Δ、绝对门结果。
3. **固定证据合同随 Task 书一起派。** W1 静帧不足以评价 V5，L2 poster 又滞后一批。
   派发时即锁首幕/POI/移动端机位、动态段时长、poster 是否需要重拍和 raw 工件保留；
   不等实现结束后补证。
4. **并行按文件域和语义耦合双重判断。** W3 的 E8/E9 文件域、语义均正交，适合并行；
   B2/ATM 虽可能少量文件不重叠，却共同改变同一主帧和评分归因，故串行。stacked PR
   只能跨“等待合入”，不能跨审计硬门。
5. **先修失败主题，不追加新主题赌总分。** L2 A-tail 的正确做法是 A-plus 定向补洞后
   再解锁 Tier B。Loop 3 延续同纪律：ATM 若未抬 V2，先修 ATM；不得用 B3/B5 把总分
   勉强推过 68。父代理每轮最多保留一个“条件追加位”，其余自动顺延。

## 推荐首批派发

建议首批派发 **2 个 Task，并行**：
