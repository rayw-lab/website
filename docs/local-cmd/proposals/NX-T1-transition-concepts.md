## 一、现有机制与工程铁律约束

1. **城侧 `PoiArrival` 管线**：
   - 圈内按 E 触发 → 若注册表有该楼 `poi_showcase-*` 机位，启动 **0.8s tween 缓动** 至机位。
   - 缓动就位后进入 **0.4s 定帧驻留（ADR-4 锁定，严禁修改时长）**。
   - 定帧起帧由 `mountHoldOverlay()` 挂载一次性全屏边缘霓虹脉冲（`--poi-hold-neon: #a855f7`，400ms CSS 呼吸淡出后自动卸类）。
   - 定帧期满（0.4s）触发 `this.navigate?.()`，执行 `location.assign('/world/agent-nexus/?from=city&poi=agent-nexus')`。
   - 驾驶输入（`RELEASE_ACTIONS`）同帧中断，立即交还玩家跟随并撤销 navigate。
   - `prefers-reduced-motion` 跳过 0.8s tween 直切 showcase 定帧，定帧 0.4s 照常驻留并跳转。
2. **跨文档跳转（MPA）的天然两段性**：
   - 本站为 Astro 静态多页应用（MPA），`location.assign` 是真实的浏览器顶层文档切换。
   - 页面卸载至新页渲染存在约 50ms~180ms 的解析窗口期。若两端底色不一致，必然爆发白闪。
   - 因此转场必须拆分为两段互锁工程：**城页离开前的收束（≤0.4s 定帧窗）** ⊕ **展厅页到达后的释放（`HallChrome` 与 `Yin.astro` 联动）**。
3. **性能与预算红线**：
   - 展厅新增动效 JS ≤12KB gzip；
   - 严禁劫持原生滚轮；
   - `prefers-reduced-motion` 必须具备 100% 可用的静态/淡入降级形态。

## 二、本楼机位建议：`poi_showcase-agent-nexus`

### 1. 推荐参数与几何解算

经 `tools/camera/audit-shot-ndc.mjs` 严密投影数学解算与多参数枚举，建议机位参数如下（对应已在 `src/data/camera-shots.json` 闭环验证的数值）：

```json
{
  "mode": "poi",
  "status": "proposal",
  "anchor": { "type": "building", "buildingId": "agent-nexus" },
  "spherical": { "phiDeg": 70, "thetaDeg": 45, "radius": 170 },
  "lookAtHeight": 50,
  "lateral": -16,
  "notes": "NX-W7 进楼前奏机位：楼 (-52,-52) 40×40×96，泊车圈 (-28,-28) 朝向 315°（车头对楼东南角）。机位沿东南对角线 θ=45° 退到 170 远、φ=70，lookAtHeight 50 把 96 高塔身整楼纳入；lateral -16 让塔偏右、左侧留夜空给转场墨团起笔。数值由 tools/camera/audit-shot-ndc.mjs 枚举取首个双门全过解：ndc.x ∈ [-0.127, 0.457]，八角点 8/8 入帧。",
  "projectionAudit": {
    "buildings": ["agent-nexus"],
    "gates": [
      { "building": "agent-nexus", "type": "maxAbsNdcX", "limit": 0.85 },
      { "building": "agent-nexus", "type": "inFrame" }
    ]
  }
}
```

### 2. 数值制定理由与对齐逻辑

| 维度 | 数值 | 严密物理与视听理由 |
|---|---|---|
| **锚点与朝向** | `anchor: agent-nexus`<br>`thetaDeg: 45°` | 泊车位在 `(-28, -28)`，大楼中心在 `(-52, -52)`，车头朝向 315°（正西北）。机位设在东南象限（$\theta = 45^\circ$），顺着车尾向车头的大透视延伸，**完全顺应玩家冲刺进站的视觉惯性**，杜绝视角倒转导致的眩晕感。 |
| **视距与仰角** | `radius: 170m`<br>`phiDeg: 70°` | 本楼高达 96m（约为 About 楼 40m 的 2.4 倍）。在 42° 水平 FOV 下，必须退至 170m 远、俯角 20°（`phi: 70°`），才能在不产生严重鱼眼畸变的前提下，将 96m 塔身完整纳入画幅。 |
| **注视高度** | `lookAtHeight: 50m` | 瞄准 96m 塔身中轴（约 48-50m 处）。若像 About 楼设在 10m，塔顶必然刺穿画面上缘出画（首版测试曾出现 $NDC.y > 1.1$ 的出画事故）。设定在 50m 后，实测八角点纵向 $NDC.y \in [-0.997, 0.896]$，底座扎根街面，塔顶留有约 10% 夜空呼吸感。 |
| **偏轴侧移** | `lateral: -16m` | **最关键的构图导演意图**：将相机向左偏轴平移 16m，使 96m 巨塔被整体推向屏幕中央偏右（$NDC.x \in [-0.127, 0.457]$，严格守住 $\le 0.85$ 门槛）。**大楼偏右，在画面左上方留出近 40% 的深邃暗夜空白——这恰好与展厅 S0 墨滴坐标 (36%, 40%) 形成精准的屏幕空间重合！** |

### 方案一：【墨拓化境 · 宣纸返生】（Ink-Rubbing Genesis & Paper Rebirth）⭐ 核心首推

#### 1. 一句话概念
0.8s 运镜切入主塔偏轴仰角，定帧 400ms 内科技城被瞬间抽干色彩压印成汉唐金石墨拓，一团浓墨自车位爆破吞噬全屏；跨文档暗墨安全帘接驳后，整屏黑墨在展厅端被宣纸纤维「反向虹吸干涸」，精准向心收缩回开篇 (36%, 40%) 的那一滴活墨。

#### 2. 逐帧分镜（ms 级时序）

```
【城页阶段 (0 ~ 1200ms)】
├─ 0ms ~ 800ms (Camera Tween)
│  └─ 按 E 触发，相机 0.8s 平滑飞升至展示机位 (108m 高空，俯视偏轴构图)。
│     车身平稳刹停，主塔紫色霓虹 #a855f7 亮起，背景街景产生微弱径向运动模糊。
├─ 800ms ~ 900ms (定帧起帧 · 墨拓压印)
│  └─ 相机锁定到位，0.4s 定帧起步！
│     全屏挂载一次性滤镜：contrast(280%) grayscale(100%) brightness(0.7)。
│     五彩斑斓的赛博城瞬间被抽干，坍缩为一张冷峻沧桑的「黑白石木拓片」，
│     建筑边缘霓虹转化为枯焦飞白，窗格光点化作宣纸上的斑驳拓痕。
├─ 900ms ~ 1180ms (墨破虚空 · 吞噬全城)
│  └─ 泊车圈（左侧近处车位）下方，一团高浓度的松烟焦墨 (#1c1f26) 如深水炸弹般炸裂！
│     墨迹沿纤维湍流向全屏以指数级迅速蔓延，将黑白拓片层层溶解遮盖。
│     至 1180ms 时，整块屏幕 100% 被深邃的焦墨色 (#1c1f26) 彻底淹没。
└─ 1200ms (定帧期满 · 墨中交卷)
   └─ 严格满足 ADR-4 0.4s 节点，PoiArrival.finish() 执行 location.assign()。
      此时视口处于极致纯黑墨底，无任何光污染。

【跨文档接驳隙 (~80ms ~ 150ms)】
└─ 展厅页 WorldHallLayout 识别 ?from=city，HTML 根节点在 CSS 渲染前即生效
   背景色 #1c1f26（纯墨遮幕），抹平 MPA 文档加载解析的白屏缝隙，达成 0 闪烁感知。

【展厅页阶段 (0 ~ 1600ms)】
├─ 0ms ~ 350ms (反向虹吸 · 宣纸返生)
│  └─ 展厅 DOM 与 WebGL InkEngine 初始化就绪。
│     黑色遮罩启动反向毛细管收缩（通过径向遮罩向 (36%, 40%) 剧烈坍缩）。
│     米色宣纸底色 (#efe9dc) 如同干渴的海绵从四周疯狂吸走水分与多余墨迹，
│     铺陈出温润、粗粝的传统生宣质感。
├─ 350ms ~ 550ms (聚气凝神 · S0 接力)
│  └─ 收缩到极致的全屏黑墨，在 (36%, 40%) 处精准收聚为一个高密度的墨核（半径约 0.072）。
│     S0 Yin.astro 的 InkEngine.drop(0.36, 0.60, 0.072, [1.3,1.3,1.3], 19)
│     在 t=0.4s 正式点火，墨核如心脏起搏般向外洇开第一圈微涡与羽化边缘！
└─ 550ms ~ 1500ms (题款浮印 · 万象归心)
   └─ 墨幕完全销毁。右侧竖排宋体题款「会话即笔迹 收据即印」微展淡入。
      朱砂印章 (#9e2a2b)「3025 四十日」如金石铿锵落定。
      顶部 HallChrome 悄然亮起紫红状态点与探索进度。
```

#### 3. 画面元素与色彩体系
- **起幅（赛博城）**：夜空深蓝 `#05070d`、主塔专属霓虹紫 `#a855f7`、车尾警示红 `#ef4444`。
- **转折（墨拓态）**：拓印焦炭黑 `#121316`、反差宣纸白 `#e2e8f0`、金属灰白 `#94a3b8`。
- **定幅（展厅态）**：手工温润宣纸 `#efe9dc`、传统松烟焦墨 `#1c1f26`、收据朱砂印 `#9e2a2b`。

#### 4. 声音设计（可选，静音优先，仅在开启全局音效时触发）
- `800ms`：赛博引擎轰鸣突然被极窄低通滤波截断，伴随一声如「拓包重重夯在石碑上」的沉闷撞击音（30ms Sub-bass）。
- `展厅 350ms`：万籁俱寂中，一声极为清脆空灵的「水滴落入墨砚」的微响（Water Drop transient），余音袅袅，沉入绝对宁静。

#### 5. 工程实现草图
- **城侧改动（`PoiArrival.ts` / CSS）**：
  不修改 0.4s 时长常量！利用既有的 `mountHoldOverlay()` 机制，在 `world-poi-hold-pulse` 样式中引入全屏合成器层：
  ```css
  /* 拓片与吞城遮罩：硬件加速合成层 */
  .world-poi-hold-pulse #world-canvas {
    filter: grayscale(1) contrast(260%) brightness(0.65);
    transition: filter 0.12s ease-out;
  }
  .world-poi-hold-pulse::before {
    content: "";
    position: fixed; inset: 0; z-index: 50; pointer-events: none;
    background: radial-gradient(circle at 35% 65%, #1c1f26 0%, #1c1f26 20%, transparent 70%);
    animation: poi-ink-swallow 0.38s cubic-bezier(0.4, 0, 0.2, 1) forwards;
  }
  @keyframes poi-ink-swallow {
    0% { transform: scale(0.1); opacity: 0; }
    40% { opacity: 0.95; }
    100% { transform: scale(4.5); opacity: 1; background: #1c1f26; }
  }
  ```
- **展厅侧改动（`WorldHallLayout.astro` / `Yin.astro`）**：
  在 `<WorldHallLayout>` 内注入内联脚本与零延迟遮罩（仅限 `?from=city` 命中）：
  ```html
  <div id="nx-transit-mask" class="nx-transit-mask" aria-hidden="true"></div>
  <style>
    .nx-transit-mask {
      position: fixed; inset: 0; z-index: 9999; pointer-events: none;
      background: #1c1f26;
      /* 径向收缩至 (36%, 40%) */
      mask-image: radial-gradient(circle at 36% 40%, transparent 0%, #000 0%);
      animation: nx-ink-dry 0.45s cubic-bezier(0.16, 1, 0.3, 1) forwards;
    }
    @keyframes nx-ink-dry {
      0% { mask-image: radial-gradient(circle at 36% 40%, transparent 0%, #000 0%); }
      100% { mask-image: radial-gradient(circle at 36% 40%, transparent 100%, #000 100%); opacity: 0; }
    }
  </style>
  ```
  `Yin.astro` 检测到 `?from=city` 时，直接将开场 `drop` 的起手延迟由原本的 `t > 0.4` 对齐至遮罩收敛完成的瞬间（约 380ms），形成物理上的严密对接。

#### 6. 预算与风险
- **代码预算**：城侧 CSS 增量 ~320 bytes，展厅侧 CSS+内联逻辑 ~450 bytes，gzip 后远低于 1KB，完全不侵占展厅 12KB 门槛。
- **风险与防线**：若低端设备发生页面切换卡顿（网络阻塞 > 1s），墨幕在 600ms 时强制触发 CSS 兜底淡出，绝不让用户长时间面临黑屏。

#### 7. `prefers-reduced-motion` 降级
- 城侧：跳过 0.8s tween 直切 showcase 定帧；不启用墨拓滤镜与爆破动画，定帧 0.4s 仅做平缓的 200ms 全屏黑淡出。
- 展厅侧：无反向收缩动画，遮罩直接透明度渐出（300ms fade-out），S0 墨滴与文字直接在位（利用既有的 poster 静态展示策略）。

### 方案二：【紫霓引线 · 笔洗化界】（Violet Thread & Brush-Wash Transmutation）

#### 1. 一句话概念
按 E 刹停后，主塔与车位的霓虹紫（#a855f7）超负荷熔断形成一道冲天离子笔触，随后整座三维城市如沉入清澈的「笔洗」缸底，被自上而下倾泻的温润墨水洗练稀释；展厅到达时水面微澜平息，水底沉淀凝结为纸上的一滴朱砂印与开篇墨华。

#### 2. 逐帧分镜（ms 级时序）
- **城页阶段（0 ~ 1200ms）**：
  - `0ms ~ 800ms`（Tween）：相机冲向主塔正立面，外立面 `#a855f7` 发光材质的泛光强度（emissive）线性增强至 350%，车周产生电离辉光。
  - `800ms ~ 920ms`（离子过载）：定帧起步！主塔与车身之间拉出一道刺破苍穹的极细紫色电弧（如毛笔凌空悬腕的提笔），全屏爆发出柔和的高动态范围（HDR）白紫辉光。
  - `920ms ~ 1200ms`（笔洗注墨）：过载的光晕并未炸碎，而是如悬浊液遇水般，从天幕顶端滚滚注入大面积半透明的青黑墨浪（利用 CSS 垂直梯度遮罩 + 模糊滤镜），整座城市像在笔洗缸中轻轻晃荡两下，所有金属与光影迅速被水体稀释降解，定帧结束时全视口呈现为深水静谧墨蓝黑色。
- **展厅页阶段（0 ~ 1500ms）**：
  - `0ms ~ 400ms`（波光潋滟）：展厅展示层就绪，页面浮现一层极淡的 SVG 扰动波纹（模拟水面泛开的微澜），深黑色的水体向四周排开。
  - `400ms ~ 700ms`（水落石出）：水波退尽，温润宣纸彻底显露。在波纹的中心点（36%, 40%），一团浓墨随水压自然渗入纸心，S0 开始扩散。
  - `700ms ~ 1500ms`：右侧题款伴随水汽蒸发般自然显影，钤印红光一闪落定。

#### 3. 画面元素与色彩
- 高饱和荧光紫 `#a855f7` → 电解紫白 `#e9d5ff` → 笔洗墨水蓝灰 `#1e293b` → 松烟焦墨 `#1c1f26` → 宣纸米黄 `#efe9dc`。色彩情绪由激昂电竞转入空灵禅意。

#### 4. 评价与取舍
- 极具现代视听张力，非常适合赛博朋克与传统文化的碰撞；但 SVG 水纹滤镜在低端移动端存在约 12ms 的复合渲染延迟，实现成本高于方案一。

### 方案三：【折叠残卷 · 乾坤易质】（Origami Scroll & Spatial Inversion）

#### 1. 一句话概念
0.8s 推进展示机位时，整座赛博城市的三维空间沿建筑棱线与地平线如古籍册页般向中央对折合拢；定帧 0.4s 瞬间被强行拍平为一张平铺的空白生宣纸，跨页到达时长卷向右侧横向拉开（直接呼应 S1 的横向墨流长卷），在左上折痕处渗出开篇墨滴。

#### 2. 逐帧分镜（ms 级时序）
- **城页阶段（0 ~ 1200ms）**：
  - `0ms ~ 800ms`（Tween）：相机急速拉升并向大楼右侧推入（对角构图）。
  - `800ms ~ 1200ms`（空间折叠）：定帧 400ms 内，屏幕两侧被无形的折纸法则支配，三维画布通过 CSS `perspective` 与 3D Transform 沿中轴向内合拢折叠，整个 3D 城市在两翼对折中收束为一道极薄的平面折痕，翻转出背面纯净的宣纸米色 `#efe9dc`。
- **展厅页阶段（0 ~ 1400ms）**：
  - `0ms ~ 400ms`（展卷铺纸）：展厅载入，画面从中轴折痕向两侧平滑展开（呼应中国传统册页「推蓬装」或「经折装」的手感）。
  - `400ms ~ 800ms`（折痕渗墨）：展平的纸面上，受压折痕最深的交点（36%, 40%）处因纤维断裂而自然渗出一滴饱含毛细扩散的焦墨，S0 启动。

#### 3. 画面元素与色彩
- 强烈的空间几何结构感：从复杂的都市网格直接折叠成一维线条，再展开为二维纸面。色彩从全彩直接翻转至单色宣纸底。

#### 4. 评价与取舍
- 概念极其前卫，与 S1「墨流长卷」的纸质空间隐喻高度同构；但三维 CSS 容器折叠在部分移动端 Safari 内核中容易引起 Canvas 纹理丢失或重绘闪烁，容错率较低。

## 六、「明确没证的」（Unverified Claims）

依据严谨工程师纪律，不编造、不粉饰，本提案中以下技术断言尚未在目标全量环境完成端到端实证：

1. **`UNVERIFIED` · WebGL Canvas 叠加高强度 CSS Filter 在 iOS Safari 的帧率底线**：
   方案一在 400ms 定帧起帧对运行中的 3D Canvas 挂载 `contrast` 与 `grayscale` 滤镜。在 Desktop Chrome 上已证实走 GPU 合成层（Compositor），但在 iOS WebKit 某些低内存机型上，对大尺寸 WebGL Canvas 应用复合 Filter 可能触发 CPU 离屏拷贝，存在掉帧至 30fps 以下的潜在风险（未在真机实测）。
2. **`UNVERIFIED` · Chrome 跨文档 View Transitions API 在带有路径 Base 时的稳定性**：
   本工程部署于 GitHub Pages 项目路径（`base: '/website'`）。Chrome 126+ 跨文档 View Transition 在带有多级路径前缀且存在静态重定向时，是否能 100% 触发 `::view-transition` 伪元素尚未在生产构建态下跑通 E2E 断言。**因此本方案将 CSS 墨幕作为 P0 基线，View Transition 仅作为 P2 渐进增强。**
3. **`UNVERIFIED` · SwiftShader 极端掉帧下的墙钟与时基对齐**：
   在 CI 的无 GPU 环境下，SwiftShader 渲染帧率可能低至 1~3fps。`PoiArrival.ts` 的定帧受 `ticker.delta`（游戏秒）驱动，而 DOM 样式的 `@keyframes` 受浏览器墙钟驱动。在极端掉帧下，400ms 墙钟可能早于 0.4 游戏秒走完，虽然代码中 `expireHoldOverlay()` 具备兜底机制，但定帧画面与墨拓滤镜是否能在单帧截图中严格保持同框，仍需专用 QE 探针复核。
