## NX-W17 回城协议批次（2026-09-04）

### 1. 新增全局类名先查重
- 触发：楼侧退场遮罩取类名 `.hall-exit`。
- 症状：遮罩被 `src/styles/hall.css:746` 已有 `.hall-exit`（展厅出口链接块）的纸白底覆盖，四帧截图全白；computed `::before.transform` 读到 `none`。
- 根因：新类名与已有全局类撞名，样式互相覆盖。
- 判据：新加全局类名前先 `grep -rn "\.<name>\b" src/styles` 一次。
- 修法：改名 `.hall-leave-veil` 后恢复正常。

### 2. 跨「重渲染时刻」的过渡动画用渲染帧驱动
- 触发：城侧幕布收拢用 CSS keyframes 900ms 挂在 `data-world-state=car_ready`，SwiftShader 环境。
- 症状：探针一观测到 car_ready，动画已在终态（transform 0.001、visibility hidden）。
- 根因：car_ready 后主线程被 shader 编译占住 >1s，CSS 动画时钟照走、帧没画出来。
- 判据：跨「重渲染时刻」的过渡动画不用墙钟驱动，用渲染帧驱动。
- 修法：随游戏 ticker 逐帧写 `--return-k`，帧真正画出来才推进。

### 3. zsh 批跑门命令要过 `sh -c`
- 触发：zsh 里 `for g in "node a.mjs" "node b.mjs"; do $g; done` 批跑五门。
- 症状：五个门全 rc=127 零耗时——是驱动层故障不是门红（gate-self-harm 式四再现）。
- 根因：zsh 对 `$g` 不分词，`node a.mjs` 整串被当单个命令名去找。
- 判据：rc=127 且零耗时＝命令没被跑起来，先查驱动再谈门。
- 修法：循环体改 `sh -c "$g"`。

### 4. 观测脚本进 worktree、导入用 `@playwright/test`
- 触发：在项目外目录（scratchpad）写脚本 `import { chromium } from 'playwright'`。
- 症状：解析不到包，脚本起不来。
- 根因：scratchpad 在包解析范围外；可用导入名是 `@playwright/test` 不是 `playwright`。
- 判据：模块解析失败先核两处——脚本目录在不在项目内、导入名对不对。
- 修法：脚本挪进 worktree `.tmp/`，导入改 `@playwright/test`。
